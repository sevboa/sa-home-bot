# Клиентские конфиги

## sing-box для Hiddify (`reality/client_config.py`)
Только stdlib; QR здесь не рисуем (`vpn/qr.py`, `deploy/reality-client.py`). Целимся в схему sing-box >= 1.11 (`format: "binary"` для `.srs`). Имя профиля задаёт имя файла, не содержимое. `all_proxy=False` (гость в РФ): заблокированное → туннель, РФ-геолокация и always-direct → напрямую, неопознанное → туннель (`final: "proxy"`, чтобы обход не ломался на свежих блокировках); `all_proxy=True` (гости вне РФ): всё в туннель, напрямую только банки/госуслуги. DNS: заблокированное резолвим через туннель (обход DNS-спуфинга ТСПУ), остальное напрямую. У DoH Яндекса адрес — домен, поэтому нужен `address_resolver` (`bootstrap-dns`, 77.88.8.8 напрямую): без него sing-box 1.11 отвергает весь конфиг (`missing address_resolver`) — так было с 2026-09-08 до 2026-10-19; проверять `sing-box check -c`. Порядок `route.rules`: always-direct раньше блок-листа, блок-лист раньше РФ-геолокаций; тесты фиксируют относительный порядок.
`vless://` — быстрый импорт/QR без правил маршрутизации (Hiddify применит пресет «Регион: Россия»); `parse_vless_url` лежит рядом и обратна ему. Hiddify deep-link берёт имя профиля из фрагмента `#label`. Подписка (`render_singbox_multi`, 57.10): несколько стран в одном профиле, `proxy` становится selector'ом (по умолчанию urltest `auto`), поэтому правила «в туннель» ссылаются на `proxy`.
Константы: `DEFAULT_FLOW = xtls-rprx-vision`, `CLIENT_FINGERPRINT = chrome` (дефолт; отпечаток теперь поле `RealityParams.fingerprint` и `[vpn.reality].fingerprint`, ходит в vless `fp=`, sing-box `utls` и xray-пробник; в подписке сериализуется, у старых записей без поля — chrome). SNI/dest задаются по серверу в `[vpn.reality]`: `sni` (дефолт `www.google.com`), `dest` (пусто = `<sni>:443`, `RealityTransportConfig.effective_dest`); серверный `realitySettings` пока пишет `deploy/setup-reality-server.sh` (SNI аргументом); `reality.xray.reality_server_settings(sni, dest)` даёт тот же блок из `[vpn.reality]` и нужен для смены SNI на сервере (63.2.3). `RealityParams.from_config` строит параметры из `config.RealityTransportConfig` (имена полей те же; дефолт flow дублирует `config.py`, т.к. config вне зоны).

## Маршрутизация (`reality/routing.py`)
Сплит по чёрному списку: заблокированное в РФ → в туннель; РФ-геолокация и «жёстко напрямую» — мимо. Списки клиент тянет сам автообновляемыми remote rule-set (`.srs`, релиз `latest`, обновляется ежедневно) из `itdoginfo/allow-domains`: `russia_inside` (блокируемое, в т.ч. зарубежное, блокирующее российские подсети — YouTube, Instagram/Meta, X, Discord, TikTok…) → в туннель; `russia_outside` (российское, доступное только российским подсетям) → напрямую. `DIRECT_SUFFIXES` (always-direct: госуслуги, НСПК/СБП, банки, маркетплейсы и повседневные РФ-сервисы, которым зарубежный IP ломает вход) идут РАНЬШЕ блок-листа — страховка от попадания банка в `russia_inside` и режима «всё через туннель» (иначе заход в банк с зарубежного IP → анти-фрод). Ведутся вручную; только регистрируемые домены (`domain_suffix` матчит и поддомены). Контрольные домены 2026-10-11: «2ip.ru видит настоящий адрес, а ifconfig.me — страну VPN» = маршруты работают (2ip.ru переадресует на соседний домен, он тоже в списке).

## xray-клиент пробника (`reality/probe_client_config.py`, 39.0.7(e))
НЕ для гостя. В netns нет TUN, нужен один локальный SOCKS5 (`curl --socks5-hostname 127.0.0.1:<port>`), xray-core умеет это нативно. `udp=true` — DNS через curl идёт тем же туннелем. Параметры сервера и UUID пробник берёт из `vless://`-ссылки, которую `issue` отдаёт любому клиенту, включая пробника (chat_id=0): пробник — другая нода, читать приватный `config.toml` сервера ей незачем и негде.

## Конфиг AmneziaWG (`vpn/awg_conf.py`)
`render` строит клиентский `[Interface]/[Peer]` (выдаются Jc,Jmin,Jmax,S1,S2,H1–H4), `parse` разбирает текст обратно (как клиент: `ключ = значение`, заголовки секций пропускаются). `AWG_KEYS` — параметры, которые клиент AmneziaVPN переносит из `[Interface]` как есть (`configKey::awgProtocolKeys`), шире выдаваемых.

### AmneziaWG 2.0 (`awg2 = true`)
При `[vpn].awg2 = true` в клиентский конфиг добавляются параметры 2.0: `S3`, `S4` (паддинг cookie- и транспортных пакетов), `I1`–`I5` (строки сигнатурных пакетов, пустая строка = ключ не выдаётся), `H1`–`H4` могут быть диапазонами вида `"a-b"`. Серверные значения должны совпадать с клиентскими. Включение 2.0 на сервере — отдельная задача (63.4.3). По умолчанию `awg2 = false`, выдача байт в байт прежняя.

## Mux выключен
Mux (sing-box `multiplex`, xray `mux`) в клиентских профилях не включён: пачка одновременных
TLS-соединений, которую открывает mux, провоцирует ТСПУ временно замораживать IP на 2–10 минут.
Страж `tests/unit/test_vpn_no_mux.py` обходит JSON-профили (`render_singbox_config` в обоих
режимах `all_proxy`, `render_singbox_multi`, `render_probe_client_config`) и `vless://`-ссылки
(`render_vless_url`) и гарантирует отсутствие ключей/параметров `mux` и `multiplex`.

## Запасные профили Reality (`spare_fingerprints`, `expand_spares`)
`[vpn.reality].spare_fingerprints` — список дополнительных TLS-отпечатков (например, `["firefox", "edge"]`). При непустом списке подписка (Hiddify, порт 8444) отдаёт сначала основные профили стран в прежнем порядке, затем для каждого запасного отпечатка — копии тех же профилей с заменой `fingerprint` и суффиксом в имени ` · <fp>`. В vless-ссылке это `fp=<fp>`, в sing-box — `utls.fingerprint = "<fp>"`, тег outbound — `<страна> · <fp>`. Старые клиенты получают первый профиль с прежним отпечатком (по умолчанию `chrome`), поэтому совместимость сохраняется. Запасной SNI в этой задаче НЕ делается — сервер принимает только SNI из своего `serverNames`; если нужен другой SNI, расширяйте `serverNames` на сервере (63.2.3).

## Имена записей подписки (решение владельца 2026-11-21)
Имя записи = флаг страны + технология + короткий маскировочный домен: `🇳🇱 Reality google`, `🇳🇱 Reality cloudflare` (alt), `🇺🇸 XHTTP azgez`. Слов «основной/резервный» нет. Флаг — первое слово `location` (при пустом `location` вместо флага `node_id`). Технология: `XHTTP` для записи с `network = xhttp`, иначе `Reality`. Короткий домен (`reality.client_config.short_domain`) — SNI записи без ведущего `www.` и без последней зоны: `www.google.com` → `google`, `azgez.com` → `azgez`. Домен понятнее порта: по нему видно, под какого «соседа» маскируется профиль. Если SNI пуст, вместо домена порт. Если у двух записей одного сервера имена совпали (одинаковый домен у основной и alt), к обеим через пробел добавляется порт: `🇳🇱 Reality google 8443`. Имена строит `ClientConfigsMixin._sub_entry_names` сразу для всех записей сервера; `_sub_links` берёт их оттуда. У AWG домена нет, там в имени будет порт (отдельное задание). Имя пира в `peers.py` («`profile_label · XHTTP`») — другое и не менялось.

## XHTTP в sing-box (2026-11-21)
`render_singbox_multi` и `render_singbox_config` принимают XHTTP-записи, подписка `?format=singbox` отдаёт их в том же профиле, что и Reality: outbound попадает и в `auto` (urltest), и в `proxy` (selector). Формат проверен по исходникам hiddify-sing-box (`option/v2ray_transport.go`) и на телефоне владельца (Hiddify 5.5.5): `vless` без `flow`, `tls.reality` как у TCP, `transport = {"type": "xhttp", "path": <path>, "mode": "packet-up", "x_padding_bytes": "100-1000"}`. Режим в sing-box всегда `packet-up`, независимо от `xhttp_mode` сервера: `auto` у Hiddify проваливается. В vless-ссылке (`render_vless_url`) режим остаётся как в конфиге сервера.

## AWG 1.0 и 2.0 в подписке (Этап 67.2, 2026-11-21)
Подписка устройства (`/sub/<token>`, все форматы) кроме Reality/XHTTP отдаёт AWG-подключения каждого сервера: `🇳🇱 AWG 1.0` (интерфейс awg0, `[vpn]`) и `🇳🇱 AWG 2.0` (awg1, `[vpn.awg_alt]`, если секция есть). Имя строит `ClientConfigsMixin._sub_awg_name` (флаг общий с Reality, `_sub_flag`).

**Почему отдельные пиры.** Приватный ключ AWG отдаётся один раз и не хранится, поэтому ключ приложения AmneziaVPN в подписку не положить. Для подписки заводятся ОТДЕЛЬНЫЕ пиры: `vpn_peers.purpose = 'sub'` (у пиров приложения `'app'`) и `private_key` (только у пира подписки, NULL у остальных). Адрес, учёт трафика, квота, сверка с бэкендом и блокировка по квоте работают для них общим кодом (они тоже `transport = 'awg'`). Версия пира определяется по подсети адреса, отдельной колонки нет. Снапшот бэкапа (`backup/snapshot.py`) несёт и эти колонки, он запечатан ключом получателя.

**Ленивая выдача** (`vpn/sub_peers.py`, `SubPeersMixin`). `_sub_links`, когда устройство найдено, доступ есть и у ноды включён AWG, для каждой версии без активного пира подписки создаёт пир под замком `_issue_lock` с повторной проверкой внутри (два одновременных запроса не создают два пира). Пробник (`PROBE_CHAT_ID`) пиров подписки не получает. Существующие устройства получают пиры при следующем обновлении подписки. Пир с ушедшим публичным ключом сервера (`server_pubkey` не совпал) отзывается и выдаётся заново.

**Пиры подписки не видны как подключения устройства**: исключены (`purpose = 'app'`) из `_peers_for_chat`, `_mark_broken`, `_active_labels`, `_active_row`, `_retire_upgraded` (проверка активного нового пира), `_device_online`, `check_restore`, счётчика `active_peers`. В `_device_usage` их трафик входит в общий расход устройства, но не в расход AWG-подключения приложения. Действие `peers` отдаёт поле `purpose`. Когда у устройства на ноде не осталось активных app-пиров (`_revoke`), его пиры подписки тоже отзываются.

**Провод между нодами.** Ответ `sub_links` получает `awg_entries` (список `AwgSubEntry.to_wire`, поле есть только при непустом списке). `resolve_subscription` собирает их со всех нод в `Subscription.awg_entries`; устаревший ответ умершей ноды хранится в `_sub_stale` вместе с обычными записями.

**Отрисовка** (`subscription.render_body`). vless/plain/base64: после vless-строк на каждую AWG-запись две строки, `amneziawg://` (v2RayTun) и `awg://` (Hiddify); формат проверен на телефоне 2026-11-21. sing-box: верхнеуровневый ключ `endpoints` (`type = awg`, проверен на Hiddify 5.5.5). Теги AWG входят и в selector `proxy`, и в urltest `auto` (решение владельца 2026-11-21, хотя в Hiddify AWG иногда отваливается). Без AWG-записей вывод прежний байт в байт. Страница `/s/<token>` и мастер бота не менялись.
