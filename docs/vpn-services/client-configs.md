# Клиентские конфиги

## sing-box для Hiddify (`reality/client_config.py`)
Только stdlib; QR здесь не рисуем (`vpn/qr.py`, `deploy/reality-client.py`). Целимся в схему sing-box >= 1.11 (`format: "binary"` для `.srs`). Имя профиля задаёт имя файла, не содержимое. `all_proxy=False` (гость в РФ): заблокированное → туннель, РФ-геолокация и always-direct → напрямую, неопознанное → туннель (`final: "proxy"`, чтобы обход не ломался на свежих блокировках); `all_proxy=True` (гости вне РФ): всё в туннель, напрямую только банки/госуслуги. DNS: заблокированное резолвим через туннель (обход DNS-спуфинга ТСПУ), остальное напрямую. Порядок `route.rules`: always-direct раньше блок-листа, блок-лист раньше РФ-геолокаций; тесты фиксируют относительный порядок.
`vless://` — быстрый импорт/QR без правил маршрутизации (Hiddify применит пресет «Регион: Россия»); `parse_vless_url` лежит рядом и обратна ему. Hiddify deep-link берёт имя профиля из фрагмента `#label`. Подписка (`render_singbox_multi`, 57.10): несколько стран в одном профиле, `proxy` становится selector'ом (по умолчанию urltest `auto`), поэтому правила «в туннель» ссылаются на `proxy`.
Константы: `DEFAULT_FLOW = xtls-rprx-vision`, `CLIENT_FINGERPRINT = chrome`. `RealityParams.from_config` строит параметры из `config.RealityTransportConfig` (имена полей те же; дефолт flow дублирует `config.py`, т.к. config вне зоны).

## Маршрутизация (`reality/routing.py`)
Сплит по чёрному списку: заблокированное в РФ → в туннель; РФ-геолокация и «жёстко напрямую» — мимо. Списки клиент тянет сам автообновляемыми remote rule-set (`.srs`, релиз `latest`, обновляется ежедневно) из `itdoginfo/allow-domains`: `russia_inside` (блокируемое, в т.ч. зарубежное, блокирующее российские подсети — YouTube, Instagram/Meta, X, Discord, TikTok…) → в туннель; `russia_outside` (российское, доступное только российским подсетям) → напрямую. `DIRECT_SUFFIXES` (always-direct: госуслуги, НСПК/СБП, банки, маркетплейсы и повседневные РФ-сервисы, которым зарубежный IP ломает вход) идут РАНЬШЕ блок-листа — страховка от попадания банка в `russia_inside` и режима «всё через туннель» (иначе заход в банк с зарубежного IP → анти-фрод). Ведутся вручную; только регистрируемые домены (`domain_suffix` матчит и поддомены). Контрольные домены 2026-10-11: «2ip.ru видит настоящий адрес, а ifconfig.me — страну VPN» = маршруты работают (2ip.ru переадресует на соседний домен, он тоже в списке).

## xray-клиент пробника (`reality/probe_client_config.py`, 39.0.7(e))
НЕ для гостя. В netns нет TUN, нужен один локальный SOCKS5 (`curl --socks5-hostname 127.0.0.1:<port>`), xray-core умеет это нативно. `udp=true` — DNS через curl идёт тем же туннелем. Параметры сервера и UUID пробник берёт из `vless://`-ссылки, которую `issue` отдаёт любому клиенту, включая пробника (chat_id=0): пробник — другая нода, читать приватный `config.toml` сервера ей незачем и негде.

## Конфиг AmneziaWG (`vpn/awg_conf.py`)
`render` строит клиентский `[Interface]/[Peer]` (выдаются Jc,Jmin,Jmax,S1,S2,H1–H4), `parse` разбирает текст обратно (как клиент: `ключ = значение`, заголовки секций пропускаются). `AWG_KEYS` — параметры, которые клиент AmneziaVPN переносит из `[Interface]` как есть (`configKey::awgProtocolKeys`), шире выдаваемых.
