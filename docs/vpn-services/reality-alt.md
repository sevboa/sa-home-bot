# Второй вход Reality (63.2.7)

## Зачем
У входа Reality в xray один `dest` и один список `serverNames`. Смена SNI на месте отключила бы всех
клиентов до обновления подписки (до 12 часов), а статические ссылки `vless://` сломала бы навсегда.
Поэтому рядом со старым входом `reality-in` (порт 8443) поднимается второй вход `reality-alt`: свой
порт, свой SNI и `dest`, те же закрытый ключ и `short_id`, те же клиенты (email и UUID). Старый вход
не меняется, xray не перезапускается, текущие соединения не рвутся. Закрытие старого входа решает
владелец отдельно.

## Настройка
Секция `[vpn.reality.alt]` в конфиге сервера: `port` (по умолчанию 2083), `sni`, `dest` (пусто:
`<sni>:443`), `inbound_tag` (по умолчанию `reality-alt`). Порт и тег не должны совпадать со старым
входом (валидатор `RealityTransportConfig`). Без секции поведение и вывод прежние байт в байт.
Параметры клиента: `RealityParams.alt_from_config`.

## Сервер
- `nodectl fix`, fixup `reality-alt-inbound` (`node/fixups/vpn_server.py`): дописывает вход в
  `~/.config/xray/config.json` (копия `realitySettings` старого входа с подменой `dest` и
  `serverNames`, права файла сохраняются) и добавляет его в живой xray через `xray api adi`.
  Наличие в живом xray определяется по `xray api lsi --isOnlyTags=true`. Ключи не логируются.
- fixup `reality-alt-ufw-port` открывает порт в ufw.
- `deploy/setup-reality-server.sh` при повторном запуске сохраняет вход `reality-alt`.
- Клиенты: `DualXrayBackend` (`reality/xray.py`) добавляет и удаляет клиента на обоих входах. Сбои
  второго входа только в журнал, сбой основного поднимается. Статистика трафика берётся только с
  основного входа. Сверка `reconcile_clients` идёт по каждому входу отдельно. После fixup новый вход
  пустой, клиентов на него добавляет сверка при старте службы `vpn`: после включения
  перезапустить службу `vpn` (не xray).

## Подписка и выдача
- `_sub_links` отдаёт прежнее поле `entry` (старый вход) и, при alt, `entries` из двух записей. Нода
  старой версии понимает `entry`, новая разбирает `entries or [entry]`.
- Запись второго входа: имя `<страна> · 2`, `SubEntry.is_alt`. Сортировка ставит все alt после
  обычных, `expand_spares` строит запасные отпечатки только из alt (когда они есть). Карточка «Страны»
  на странице подписки alt-записи не показывает.
- Выдача: новая ссылка и QR человеку ведут на новый вход, ответ содержит ещё `alt_share_url`.
  Пробник (`PROBE_CHAT_ID`) по-прежнему получает `share_url` на старый вход, иначе мониторинг старого
  входа незаметно переехал бы на новый.

## Пробник
- Служба `vpn` при alt отдаёт в состоянии `probe_transports` = транспорты + `reality_alt`.
  `transports` не меняется: выпуска ключей по `reality_alt` нет.
- `probe_targets` берёт `probe_transports or transports`. Слот `reality_alt` выпускается с
  `transport="reality"` и берёт `alt_share_url`.
- Номера слотов: обычные как раньше по порядку, `reality_alt` получают
  `ALT_SLOT_INDEX_BASE (32) + позиция сервера среди всех серверов целей`. Включение alt на одном
  сервере не сдвигает ни старые слоты, ни alt-слот другого сервера.
- Строки проверок `reality_alt` не попадают в `check` состояния службы `vpn`: значки стран и
  здоровье у гостя считаются по старому входу. Оповещения `vpn_check` показывают транспорт
  `reality_alt` как есть.
