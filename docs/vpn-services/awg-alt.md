# Второй интерфейс AmneziaWG 2.0 (63.4)

## Зачем
Параметры маскировки AmneziaWG 2.0 (`S3`, `S4`, диапазоны `H1`–`H4`, `I1`–`I5`) задаются на интерфейсе
целиком. Если сменить их на `awg0` на месте, сразу отключатся все старые клиенты. Поэтому рядом с `awg0`
поднимается второй интерфейс `awg1` со своим UDP-портом, своей подсетью и своим ключом сервера. Старый
`awg0` не меняется. Новые устройства гостей получают 2.0, старые переходят по кнопке, а старый вход
живёт, пока на нём кто-то есть. Закрытие `awg0` решает владелец отдельно.

Транспорт в базе остаётся `awg`. Интерфейс пира определяется по подсети его адреса, а не по отдельной
колонке, поэтому схема БД не менялась.

## Настройка
Секция `[vpn.awg_alt]` (`AwgAltConfig`): `interface` (`awg1`), `port` (51821), `subnet`
(`10.9.1.0/24`), `jc jmin jmax s1 s2 s3 s4`, `h1`–`h4` (число или диапазон `"a-b"`), `i1`–`i5` (пусто —
строка не пишется). Значения по умолчанию — заготовка. Боевые значения 2.0 подбираются при включении
на каждом сервере. Имя секции `awg_alt`, потому что `awg2` уже занят bool-флагом формата конфига.
Валидатор `VpnConfig` не даёт совпасть интерфейсу и порту и пересечься подсетям со старыми.
`VpnConfig.awg_alt_render_cfg()` собирает конфиг для отрисовки клиента 2.0, `awg_subnets()` отдаёт обе
подсети. Без секции поведение и вывод прежние байт в байт.

## Сервер (`nodectl fix`, `node/fixups/vpn_server.py`)
- `awg-alt-interface`: если файла `/etc/amnezia/amneziawg/<iface>.conf` нет, ключ генерируется на
  сервере (`awg genkey`), файл пишется с правами 0600 (`awg_alt_conf_content`: адрес — первый хост
  подсети, `PostUp`/`PostDown` с NAT и TCPMSS). Существующий файл не перезаписывается, иначе сменился
  бы ключ и все устройства 2.0 сломались бы. Затем `ip_forward`, `awg-quick@<iface>`.
- `awg-alt-ufw-port`: UDP-порт в ufw. `awg-alt-forward-persist`: скрипт и юнит
  `sa-home-<iface>-forward` по образцу `awg0`.
- sudoers `awg set <iface> peer *` добавляется для второго интерфейса. Без `awg_alt` проверка sudoers
  прежняя (только наличие файла), чтобы обновление не переписало sudoers на всех серверах.
- На jeeves порт открывается не только в ufw, но и в его nftables: это делает владелец скриптом.

## Служба `vpn`
- `DualAwgBackend` (`vpn/awg.py`): `add_peer` по подсети, `remove_peer` на оба интерфейса, слияние
  `transfer` и `latest_handshakes`. Сбой второго интерфейса — в журнал, сбой основного поднимается.
- Выдача: гость (`_awg_alt_for`) получает адрес в подсети 2.0 и конфиг 2.0. Пробник
  (`PROBE_CHAT_ID`) получает 2.0 только по флагу `awg_alt` в `issue` (свой слот), иначе остаётся на
  `awg0`.
- Ключ сервера берётся по адресу пира (`_server_public_key_for_address`). `_mark_broken`,
  `check_restore` (второй отпечаток `server_key:awg_alt` в `vpn_meta`) и `detect_status` подписки
  знают про обе подсети.

## Переход старого устройства (`retiring`)
- Кнопка «⬆️ AmneziaWG 2.0 <страна>» на карточке устройства появляется у AWG-подключения с
  `awg_legacy` (адрес вне подсети 2.0). Нажатие шлёт `reissue` с `keep_old`.
- Служба переводит старую строку в статус `retiring`. Пир остаётся на `awg0`, учитывается в трафике
  и сверке, его адрес занят, но в списке устройств его нет. Новое устройство той же метки выдаётся
  в подсети 2.0.
- `_retire_upgraded` (каждый проход сэмплера): как только у активного AWG-устройства той же метки
  появилось рукопожатие, старой строке пишется срок `revoked_at = сейчас + 3 дня`. По сроку строка
  уходит в `expired` и снимается с интерфейса. Для `retiring` поле `revoked_at` означает плановый срок.
- `revoke` устройства гасит и его `retiring`-строку. Обычный «Перевыпустить ключи» гасит старое сразу.
- Решение владельца 2026-11-10: гасить через 3 дня; напоминание о переходе — гостям с рукопожатием на
  `awg0` за последние 30 дней, рассылка только по его слову.

## Пробник
- Служба `vpn` при `awg_alt` отдаёт в состоянии `probe_transports` + `awg_alt` и
  `awg_alt_server_public_key`. Строки проверок `awg_alt` не попадают в `check` состояния.
- Слот `awg_alt`: индекс `AWG_ALT_SLOT_INDEX_BASE (48) + позиция сервера`, интерфейс
  `awg-probe<индекс>`, выдача `transport="awg"` с `awg_alt: true`. Свежесть конфига сверяется с ключом
  второго интерфейса. На клиенте пробника нужны `amneziawg-tools` с поддержкой 2.0.

## Бэкап
Identity хранит `awg_alt {interface, private_key}`. Восстановление подставляет ключ в существующий
файл интерфейса или собирает полный конфиг из `[vpn.awg_alt]` бэкапа. Без `awg_alt` документ и его
хэш прежние.
