# Подписка Hiddify и веб-страница (57.10–57.13)

## Токен
`vpn/subscription.py` чистый (ни сети, ни БД). Токен не содержит chat_id и нигде не хранится: 4 байта «поколения» (unix-время последнего перевыпуска/отзыва VLESS-ключа устройства на любой ноде) + 20 байт `HMAC-SHA256(секрет, "chat_id\0label\0поколение")`, всё base64url (32 символа). Любая vpn-нода пересчитывает MAC по своим активным VLESS-ключам и находит владельца (`_sub_local`), общая БД не нужна. Токен старого поколения отвергается, если хоть одна нода знает более новое — так перевыпуск гасит утёкшую ссылку (`resolve_subscription`; недоступный сосед пропускается, а его последние данные берутся из `_sub_stale`: страна не должна пропадать из подписки на время сбоя). Поколение живёт в `vpn_peers.revoked_at` снятых строк (`_device_gen`), поэтому переживает переустановку ноды из бэкапа; выпуск новой страны ничего не меняет — ссылка на телефоне остаётся живой.
Секрет — `[vpn].sub_secret`, а если пуст, производная от `[swarm].token` (он один на весь рой и входит в бэкап identity, поэтому ссылки переживают переустановку).

## Сбор ответа
`sub_links` между нодами: если у устройства здесь есть VLESS — сервер, UUID, расход и лимит гостя за месяц, поколение токена и сведения о ноде для страницы (адрес выхода, здоровье, AmneziaWG). Второй заход (`_sub_device_info`): ноды без VLESS у устройства узнают его по подписи токена (chat_id/label приходят от ноды, где VLESS есть) и сообщат про AmneziaVPN — для старых устройств, у которых VLESS только в части стран. Соседние ноды кэшируются на минуту. Параллельная загрузка страницы не должна оставить старый «ключа нет» — кэш сбрасывается при выдаче.

## Страница
`render_page` — хаб устройства: статус «VPN включён?», Hiddify одной кнопкой, страны и остаток, AmneziaVPN. Русский, на «вы», без пола, всё инлайн, автоперехода в приложения нет. Форматы подписки (`?format=`): `vless` (base64-список vless://, по умолчанию), `plain`, `singbox` (JSON с несколькими outbound). Статус «включён» определяется по адресу запроса (`detect_status`): из awg-подсети своей ноды — AmneziaWG (трафик к собственному адресу не маскарадится), с публичного адреса своей ноды — VLESS, с адреса соседа — только страна; GeoIP нет. `/where` (57.12): страница спрашивает каждую ноду из браузера; ответ `{via, exit, ip}`: `exit` — имя ноды, с чьего публичного адреса пришёл запрос, `ip` — адрес, который видит нода (2026-10-19). Решение владельца: страница проверяет именно то, что трафик до неё идёт через VPN, не «ключи на связи» (это делает мастер в Telegram). При «выключен» страница показывает, какой адрес видит каждый сервер, и подсказку про Per-App Proxy / WARP в Hiddify. AmneziaVPN, похоже, пускает трафик к своему серверу мимо туннеля — нода выхода видит настоящий адрес и молчит, а сосед видит адрес ноды выхода; если никто не сказал `via`, но кто-то назвал `exit`, страница пишет «включён — <exit>, способ AmneziaVPN» (при VLESS нода выхода сама отвечает `vless`, проверено xray-клиентом). С одной нодой так не определить. Сосед не ответил при сборке подписки (рестарт) — берутся его последние записи и последний `NodeInfo` (`_sub_stale_info`, без health и выдачи AmneziaVPN), иначе на 20–30 с кеша пропадали его адрес (`exit`) и CORS; CORS — только для страниц наших нод (CSP `connect-src`). `deep_link` без `#имени`: Hiddify показывает фрагмент без декодирования процентов, имя берёт из заголовка `profile-title` (base64; заголовки HTTP — latin-1). Отдельный профиль в Hiddify для подписки, чтобы не спутать с обычным.
`detect_platform`: android / ios (iPhone, iPad, iPod) / other; iPadOS в режиме «компьютер» — Macintosh → other (показываются обе кнопки).

## Выпуск AmneziaVPN со страницы (57.13)
POST `…/awg` (node, nonce, action), ответ — JSON только скрипту страницы: Origin/Referer того же хоста, одноразовый nonce (в ответе следующий, живёт долго — страница может лежать открытой), частота (не чаще раза в 5 с на устройство и страну, 20 в час на устройство, 120 в час на ноду; в памяти, без адресов). GET ничего не выпускает — предпросмотр ссылок и сканеры (без JS) ключей не создают. `action=issue` ключ не заменяет (есть — `exists`), замена только `action=reissue`. Ключ только в этом ответе, `no-store`. Параллельных разборов токена не больше N (каждый ходит к нодам).

## Сервер (`vpn/subweb.py`)
`/s/<токен>`, `/s/<токен>/where`, `/s/<токен>/awg`, `/s/<токен>/hiddify`, `/s/<токен>/amnezia`, `/sub/<токен>`; всё прочее и неизвестный/отозванный токен — голый 404 (снаружи не отличить), заголовок `Server` убран, IP не пишутся. Порт отдельный (не 443/8443 — там mtg и xray). TLS: есть сертификат и ключ — https, иначе http (`sub_allow_http`). Let's Encrypt на IP короткоживущий (~6 суток), продлевает внешний таймер `deploy/sub-cert.sh`; раз в `RELOAD_EVERY_S` проверяется mtime и сертификат перечитывается на том же SSLContext; появление сертификата у работавшего по http сервера пересоздаёт сайт с TLS.

## QR-коды и мостики (2026-10-19)
Каждый QR подписан, что он делает: «📲 Скачать приложение» (магазин под тип устройства), «➕ Создать подключение» (камерой телефона: https-мостик открывает приложение и добавляет подключение — можно показать другому человеку), «🔎 Для сканера внутри приложения» (Hiddify — ссылка подписки `?format=singbox`, камерой скачает JSON; AmneziaVPN — текст `.conf`). Мостик нужен, потому что камера Android схемы `hiddify://` и `vpn://` часто не открывает. `/s/<токен>/hiddify` — `hiddify://import/<подписка с маршрутами>`, на телефоне переход сразу. `/s/<токен>/amnezia#vpn://…` — ключ только во фрагменте: на сервер не уходит (ключи не храним), скрипт читает его и стирает из адресной строки; Android/компьютер — переход в `vpn://`, iOS — кнопка «Скопировать ключ». QR мостика AmneziaVPN собирается в ответе POST `…/awg` (`add_qr`, уровень коррекции L — ключ ~720 символов, версия ~22), показывается крупно (280px).

## Ключ `vpn://` AmneziaVPN
`amnezia_key.py` (57.12). Формат из исходников amnezia-client (`importController.cpp`): `vpn://` + base64url без `=` от `qCompress(JSON)` (4 байта длины big-endian + zlib). Структура — как клиент строит при импорте `.conf` с AWG: контейнер `amnezia-awg`, в нём `awg.last_config` — строка с JSON (с исходным `.conf`) и `isThirdPartyConfig: true`. MTU по умолчанию 1280 (defaultMtu Android/iOS, клиент подставляет своё). Ключ содержит приватный ключ клиента — обращаться как с `.conf`.

## Ленивая выдача Reality-пира на новом сервере (2026-11-21)
Когда в сеть добавили сервер ion и гостю открыли к нему доступ, у его старых устройств там не было
Reality-пира, и `_sub_local` ничего не находил. `resolve_subscription` уже переспрашивает такие
ноды с подсказкой `{token, chat_id, device_label}`. Теперь `_sub_links` по такой подсказке
(`_sub_lazy_issue`) выдаёт устройству Reality-пир (`_issue_locked`, `purpose='app'`) под
`_issue_lock`, повторно проверив `_sub_local` внутри замка, и отвечает как для найденного
устройства (Reality-записи и AWG-пиры подписки).

Условия: подсказка проходит тот же HMAC, что и токен (подделать пару `chat_id`/`device_label`
нельзя), не пробник и не нулевой чат, на ноде включён Reality, у гостя есть доступ, а поколение
токена не старее `_device_gen` этой ноды (отозванное на ноде устройство старым токеном не
воскрешается). Без этих условий поведение прежнее. Сбой выдачи пишется предупреждением в лог без
ключей, подписка отвечает как раньше. Событие «пир выдан» не шлётся: выдача тихая.

## Домен и порт подписки (находка 2026-11-22)
- Порт 8444 режется ТСПУ из России: SYN не доходит (проверено с vanka: на ion 8444 не доходит,
  2096, 2053, 8443, 9443, 8880 доходят). jeeves и wooster из РФ недоступны по IP целиком.
- Владелец купил домен `heyalfred.fyi`. Адрес подписки: `https://sub.heyalfred.fyi:2096/...`,
  `sub.heyalfred.fyi` указывает на ion. В Cloudflare запись только DNS (без прокси), иначе
  не пройдут http-01 и свой TLS.
- Конфиг ion: `sub_port = 2096`, `sub_public_host = "sub.heyalfred.fyi"`,
  `sub_legacy_ports = [8444]`. Служба слушает оба порта одной `web.Application`, один
  `SSLContext` на все порты (перечитывание сертификата действует на оба). Старые ссылки
  `https://<IP>:8444/...` продолжают работать. Фикс-ап ufw открывает все порты подписки.
- Сертификат один, с SAN на IP и на домен: `sh sub-cert.sh <IP> 2096 sub.heyalfred.fyi`
  (профиль shortlived для всего сертификата). Дополнительный порт 8444 в firewall открывает
  фикс-ап ufw.
- При блокировке сервера переносится A-запись `sub.heyalfred.fyi` на другой сервер: ссылка
  у гостей остаётся прежней. Условие: на новом сервере тот же порт 2096 и то же имя, сертификат
  выпущен на домен.
- Бот выбирает ссылку страницы по приоритету (`page_url_rank` в
  `bot/handlers/vpn/screens.py`): https с доменным именем, затем https на IP, затем http.

## Сервер, закрытый из России, прячется из подписки (2026-11-25)
Сервер ion закрыт по IP из РФ, и люди в России получали в подписке нерабочие записи. Решение владельца
2026-11-25: `resolve_subscription` (`_sub_hide_blocked` в `vpn/subscription_links.py`) после сбора ответов
всех нод выкидывает записи (`entries`, `awg_entries`) и строку «Страны» (`nodes`) серверов, у которых
слой net в области russia (`_net_scope_levels()["russia"]`) равен down. Partial, ok и отсутствие данных
сервер не прячут. Когда сеть поднимется, сервер возвращается сам: отдельного состояния не хранится, берётся
текущий уровень, а кеш подписки (20–30 с) остаётся прежним.

Осознанный компромисс: люди вне РФ тоже не увидят этот сервер, пока он закрыт из РФ.

Предохранитель: если после фильтра не осталось ни одной записи, подписка отдаётся без фильтра, чтобы не
оставить человека с пустой подпиской. Выключатель: `[vpn] sub_hide_blocked_from_russia = false`.
