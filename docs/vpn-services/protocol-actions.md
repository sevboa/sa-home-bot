# Протокол службы vpn

`vpn/protocol.py` намеренно без импортов внутри проекта: его импортируют `bot/tools.py` и `bot/handlers/vpn.py`, не утягивая службу (и awg) в бота. Этап 33 в IMPLEMENTATION_PLAN.md — общий дизайн; этап 39 — несколько серверов (адреса ноды-держателя в протоколе нет, поиск живой через `bot/vpn_nodes.py`: `resolve_vpn_dst`/`fanout`). Строки `ACTION_*`/`EVENT_*`, `ERR_QUOTA_CEILING` ("vpn_quota_ceiling") и значения транспортов менять нельзя.

## Действия
- Пиры: `peers` (админ, все пиры всех гостей), `issue {chat_id, device_label}`, `reissue` (старый пир снимается, новый — тот же гость/label), `revoke`, `get_vless` (57.1, ссылка/конфиг VLESS существующего устройства без перевыпуска; UUID в `vpn_peers.public_key`).
- Подписка Hiddify (57.10): `get_subscription {chat_id, device_label}` → `{page_url, sub_url, ...}` для бота; `sub_links {token}` — служебное между vpn-нодами («есть ли у вас VLESS устройства с этим токеном»); `sub_gen` — служебное: поколение токена устройства.
- Расход и квоты: `usage` (с chat_id — свой расход, без — сводка по всем, админ), `set_quota` (админ: прямой грант месяца `{chat_id, bytes}`), `set_access {chat_id, allowed, base_gb}`, `grant_extra` (гость сам себе +`extra_step_gb`, пока не упёрся в потолок), `request_extra` (заявка админу сверх потолка), `resolve_request {request_id, approve}`.
- APK: `apk_info` (метаданные кэша, проверяет свежесть), `apk_chunk {offset, length}` (кусок для передачи через рой), `apk_set_file_id` (бот сообщает id уже загруженного в Telegram файла).
- Мониторинг: `report_check` (vpn_check пушит `{node, results: {target: {ok, ms, error}}}`), `check_now` (админ/nodectl: разослать проверки внеочередно), `check_status` (текущее состояние по всем (node, target)). Найдена нужда 2026-08-17.
- Прокси на jeeves (mtg — MTProto, microsocks — SOCKS5), 2026-08-17: `proxy_link` (tg://proxy + t.me, host/port/secret, SOCKS5-адрес), `proxy_rotate_secret` (админ: новый secret, рестарт демона), `proxy_usage` (админ: агрегатный расход + `node_limit_gb`). Секрет общий на всех — не per-guest (mtg принципиально не умеет несколько секретов в одном процессе), трафик агрегатный.
- Этап 52: `telegram_egress {observer}` → `{node, label, socks, check}` — лёгкое чтение для бота: SOCKS5-адрес ноды + свежая проба api.telegram.org через её reality-VLESS от лица `observer`. Без QR/секретов. «Здоровье маршрута до Telegram» — одна пара (`TELEGRAM_EGRESS_TRANSPORT`, `TELEGRAM_EGRESS_TARGET`) в `vpn_check_states`; протухшая строка не прячется, а помечается `stale` — решать «неизвестно» будет бот.

## Секрет-затравка прокси
`PROXY_SECRET_SEED` — секрет, развёрнутый вручную на jeeves 2026-08-13 (память telegram-bot-api-proxy-2026-08-13). Общий бутстрап-литерал для `vpn/service.py::_proxy_secret` (сидирует БД при первом старте) и `node/fixups.py::make_proxy_units_fixup` (пишет тот же секрет в юнит mtg, если файла ещё нет): оба места сходятся без похода друг к другу. Меняется только через `proxy_rotate_secret`, который правит и БД, и юнит.
Байты прокси считаются тем же дельта-механизмом (`vpn_counters` по псевдо-ключам, `vpn_peer_usage` по отрицательным peer_id — реальные получают id из AUTOINCREMENT, он положителен) и входят в общий счётчик `node_limit_gb` без правок `_check_node_limit`. Ответ несёт ноду/метку локации — секрет у каждой ноды свой (своя `vpn.sqlite:proxy_state`). Если sudoers для чтения nft ещё нет, тик сэмплера не рушится — прокси пропускается. Прокси живёт на VPS независимо от VPN-транспорта (на wooster поднят при reality-only раскладке, 2026-09-06); гейт — по факту настройки.

## События
Квотные события и `vpn_peer_issued` несут `node`/`location` (бот ставит страну сервера в текст, 57.7). `vpn_node_quota_warning` адресуется админам (общий канал VDS приближается к лимиту). `vpn_check_failed/recovered` — эмитятся только на переходе (гистерезис), это и есть «мут» повторных оповещений. `vpn_server_restored` (57.1): после reconcile на старте служба заметила смену ключа сервера (переустановка/восстановление БД), данные `{node, location, affected: [{chat_id, device_label, transport}]}`; пробника в списке не бывает; бот (`bot/vpn_notify.py`) пишет задетым по сообщению, владельцу — сводку; при пустом `affected` событие всё равно уходит. `ERR_QUOTA_CEILING`: гость упёрся в потолок самообслуживания — бот на этот код сам оформляет `request_extra`.

## Имена файлов гостю
`secret_filename` (в protocol, а не в bot/handlers/vpn.py: те же имена нужны `tool_vpn` в `bot/tools.py`, а он не может импортировать обработчик — тот тянет aiogram, и tools.py крутится ещё и в службе tasks). Вид «awg_nl_rose_123.conf» / «vls_nl_orchid.json»: тип и страна в начале (гость держит конфиги с нескольких серверов, решение 2026-09-18; без флага в `[vpn].location` остаётся только тип). У awg имя без расширения — имя тоннеля, NAME_PATTERN wireguard-android `[a-zA-Z0-9_=+.-]{1,15}`: метка времени режется до трёх цифр, имя устройства — до остатка; метка отличает выпуски одного устройства (2026-08-04). У sing-box-конфига лимита нет. Страна сервера берётся из флага-эмодзи (две regional indicator = код страны, 🇳🇱 → NL), отдельного поля не нужно.
