# Эксплуатация

## sudo и права
Долгоживущие процессы не root. `awg` вызывается через `sudo -n` на узкий sudoers-снипет (`node/fixups.py::AWG_SUDOERS`: NOPASSWD ровно на `awg show *` и `awg set <iface> peer *`, не на весь `awg-quick`, исполняющий произвольные PostUp). Генерация ключей (`awg genkey/pubkey`) root не требует — приватный ключ не должен всплывать в sudo-логе. Счётчики прокси — `sudo -n nft -j list counter inet filter <name>` (`make_proxy_firewall_fixup`, NOPASSWD на два именованных счётчика). Секрет mtg меняется БЕЗ sudo: юзер-юнит `~/.config/systemd/user/mtg.service` принадлежит пользователю службы (`ExecStart=… simple-run 0.0.0.0:443 <secret>`, секрет — последний токен строки). Общая обёртка `vpn/privileged.py::sudo_stdout`: отказ sudo → `ERR_NEEDS_PRIVILEGE` с подсказкой «по SSH выполните: nodectl fix», иное → `ERR_INTERNAL`. Путь к бинарю резолвится при каждом вызове (не кэшируется): фикс, применённый после старта службы, подхватится без рестарта.

## xray api
Юзеры и статистика — через gRPC API самого xray (`xray api adu/rmu/inbounduser/statsquery`, `127.0.0.1:10085`) без sudo и рестарта, отдельного sudoers-снипета у reality нет. Грабли `adu`: строит из сниппета ПОЛНЫЙ InboundDetour и валидирует его — нужен непустой `port` (иначе «Listen on AnyIP but no Port(s) set») и `decryption:"none"` в settings, значения должны совпадать с реальным inbound (правка матчится по `tag`); принимает только путь к файлу, не stdin; выходит с кодом 0, даже когда ничего не добавил («failed to build config») — ловится по хвосту вывода, иначе гость получил бы нерабочий конфиг, а пир осел бы в БД активным. Удаление юзера, которого уже нет в живом инстансе — успех для реконсайлера. `stats` отдаёт email → (uplink, downlink) с момента старта xray (не сбрасываем, дельту считает сервис); email не содержит `>>>`. У reality нет «хендшейка» — «было на связи» ведётся по приросту трафика.

## Сэмплер
Счётчики сервера стартуют с нуля при подъёме интерфейса; первое наблюдение пира — база 0. Ключ вчерашнего среза в `vpn_counters` — `public_key` (awg-pubkey либо xray-UUID).

## APK AmneziaWG
`vpn/apk.py` — клиент GitHub Releases (urllib + to_thread, httpx/aiohttp в проекте сознательно нет). Свежесть проверяется на КАЖДЫЙ запрос гостя (memo `APK_INFO_TTL`, чтобы двойное нажатие не давало два запроса к API); кэш на jeeves — ускоритель доставки, не источник правды о версии. sha256 из поля `digest` есть не у всех релизов — иначе сверяется только размер. Кусок на сообщение протокола — 700 КиБ (запас от `MAX_MESSAGE_BYTES` = 1 МиБ: base64 раздувает на треть, плюс конверт JSON). APK раздаётся только там, где раздают awg. Недоступность GitHub не значит, что кэша нет вовсе.

## Запуск служб
`vpn_check/app.py` — минимальная реактивная служба без БД и планировщика, со своим ServiceLink к локальной ноде для пуша `report_check`. Служба может быть развёрнута на нескольких нодах (jeeves, alfred…), единственного NODE_ID нет (`[vpn].check_nodes`). Бэкап снапшота БД напарнику (39.0.8(c)) выключен без `[backup].partner`; после изменения БД снапшот уходит вне очереди.
