# Линки роя, протокол и события

Модули: `node/peers.py`, `node/discovery.py`, `node/watch.py`, `node/app.py`, `proto/*`.

## Маршрутизация («спроси любого»)
Запрос с чужим `dst` нода пересылает сама: к удалённой ноде по `dst.node` (`[[swarm.nodes]]` плюс
персистентное состояние) или к локальной службе по `dst.service`. Клиент не знает, кто исполнил.
Недоступность честная и быстрая: неизвестный адресат — `unknown_dst`, известный без соединения —
`unavailable`. Маршрут строится по ИМЕНИ службы, а не по строке назначения целиком
(`telegram-bot@alfred:standby` — всё та же служба `telegram-bot`). События пиров ретранслируются
клиентам ноды с сохранением исходного `src`.

## PeerLink
- Фоновая задача держит соединение и переподключается. Адресов у соседа несколько (этап 24: LAN,
  tailscale, названные в hello): порядок проб — последний удачный, затем локальные, затем оверлей
  (`proto/endpoints.endpoint_rank`; `sorted` стабилен, конфиг важнее выученного).
- `CONNECT_TIMEOUT_S` = 5 с на одну попытку (connect + hello): без потолка адрес без маршрута съедал
  ОС-таймаут TCP-connect (десятки секунд) и рабочий адрес не пробовался. `MAX_ENDPOINTS` — потолок
  списка адресов соседа.
- Ответивший чужим именем — кандидат последней очереди (имя в конфиге человек пишет как угодно),
  но ответивший СВОИМ именем нашей ноды (`_self_node`) никогда не годится: адрес соседа переехал
  (DHCP без резервации отдал его другой машине, в т.ч. нам) — иначе линк ходит по кругу
  «подключился к себе -> запрос не доехал -> переподключение», а PresenceWatcher рапортует
  ложное «вернулась в строй» (находка 2026-08-04).
- `learn_endpoints`: адреса последнего hello — полная и единственная правда о соседе, а не добавка
  к накопленному (раньше выученное только прирастало, и стухший адрес жил в списке вечно; находка
  2026-08-04). Loopback от соседа отбраковывается жёстко. Адрес, на котором связь есть сейчас,
  loopback-фильтр не проходит намеренно (unix-сокет валиден именно когда уже соединены по нему).
- Своё представление о соседе (адрес, тип, WoL, пути) обновляется только по ПОДТВЕРЖДЁННОМУ ответу
  от него самого, не по «запасному» мисматчу (инцидент 2026-08-04: в адреса «mycraft» попал
  LAN-адрес «winpc»).
- Тип машины соседа (`node_kind`) и WoL-реквизиты держатся и после обрыва: нужны именно тогда,
  когда соседа уже не спросить.
- Прикладной heartbeat (находка 2026-07-28): TCP не замечает собеседника с живым сокетом и
  зависшим процессом. Пробой служит `hello` (протокол не расширяется). `HEARTBEAT_MISSES` = 2
  промаха подряд до разрыва. Для локальных служб интервал/таймаут больше (XTTS-синтез в
  `llm/tts.py` ненадолго не пускает event loop службы ответить на hello).
- Инкарнация процесса (`NODE_INCARNATION`) едет в auth. Сервер реагирует на СМЕНУ инкарнации, а не на
  факт подключения (прод 2026-07-28: первая версия дёргала колбэк на каждый auth, и alfred с winpc
  рвали линки друг другу каждые 10 с). Сменилась -> `_note_peer` закрывает старые входящие
  соединения (до этого после трёх ребутов winpc на alfred висело четыре ESTAB) и вызывает
  `reconnect_now` у исходящего линка.
- Флаги `_dropping` / `_stopping`: свой же сброс соединения (heartbeat/reconnect_now) неотличим от
  отмены `stop()`; `_stopping` старше `_dropping`. Флаг ставится ДО cancel (этап 29: иначе «нода не
  гасится»). Соединение закрывает ровно один владелец — `_run` в finally; `ProtoClient.abort`
  синхронный (раньше close() звали параллельно из heartbeat и reconnect_now, линк после этого не
  переподключался).
- Цикл `_run` обязан переживать любое исключение (находка 2026-07-28: необработанное убивало задачу
  линка молча).
- Таймаут ОДНОГО запроса — не повод рвать линк (находка 2026-09-25: SearXNG думал ~10 с, web_search
  упёрся в таймаут, reconnect_now ронял всё соединение с mycraft, и гость видел «Альфреда нет на
  месте»). Мёртвые линки ловит heartbeat за <= ~15 с. Запрос, ушедший «в никуда» (нет ответа вовсе),
  подозрителен и переустанавливает линк сразу.
- `note_left`: сосед объявил штатный уход (`node_leaving`) — линк роняется сразу, уход помечается
  штатным; цикл переподключения стучится как обычно (connection refused дёшево) и заметит
  возвращение. Отсчёт простоя (`downtime_s`) начинается даже если линк уже оборван.

## Ретрансляция запросов по качеству связи (2026-10-18)
- Находка: Tailscale-путь alfred↔wooster деградирует (RTT 600 мс, потери 13–27 %, ~100 обрывов
  heartbeat в сутки), а через jeeves стабильно ~185 мс. Замер 20 мин: напрямую p50 254 / p90 620 /
  max 7318 мс и 3 сбоя, через jeeves p50 185 / p90 192 / max 511 мс без сбоев.
- `PeerLink` меряет RTT каждого heartbeat-hello (сглаживание `RTT_SMOOTHING`) и долю промахов за
  последние `QUALITY_WINDOW` проб. Стоимость пути: RTT + потери × `LOSS_PENALTY_MS`.
- Нода публикует таблицу своих прямых связей в hello (`links`, необязательное поле; у служб, кроме
  ноды, его нет, их hello прежний). Соседи получают её с каждым heartbeat, без новых запросов.
  Сосед без таблицы (старая версия) ретранслятором не бывает.
- `NodeRouter.route`: путь меняется, только если новый дешевле текущего на `SWITCH_RATIO` и минимум
  на `SWITCH_MIN_GAIN_MS` (гистерезис, без дребезга). Нет прямой связи — запрос идёт через соседа,
  у которого связь с целью жива. Ретранслированный запрос несёт `hops` ≥ 1 и дальше идёт только
  напрямую: петель и второго ретранслятора нет.
- Повтор через ретранслятор после обрыва прямой связи — только для `hello`/`describe`/`get_state`:
  команда могла уже выполниться, команды не идемпотентны.
- `peers_state` отдаёт `rtt_ms`, `loss`, `via`, `via_rtt_ms`; `via` — решение последнего запроса к
  этому пиру. Смена пути пишется в журнал («Маршрут к X: через Y / напрямую»).

## События и шторм ретрансляции
- `SeenEvents`: дедуп по `env.id` (uuid4, не меняется при ретрансляции). Инцидент 2026-07-17: в
  полносвязном рое из 3 нод эхо-проверка ловила только возврат к источнику, копии от разных
  соседей размножались лавиной, Telegram забанил бота 429 (retry-after 578 с) за ~7 минут. Размер
  набора 2048 (512 протекало при всплеске tool_call/task_result/llm_idle_sleep/алертов).
- Второй независимый рубеж — счётчик `hops` в конверте, `MAX_EVENT_HOPS` = 8 (диаметр полного графа 1,
  Chord — O(log n)). Нет поля в JSON = 0: ноды старых версий не ломаются.
- Эхо-проверка (`env.src.node == node_id`) только для событий ПИРОВ. Локальная служба репортует
  `src.node == node_id` не из-за эха, а потому что это её узел: `on_peer_event` и `on_local_event`
  — разные колбэки (прод 2026-07-24: `task_result` от tasks молча терялся).
- `node_joined` от связанного пира: автоподключение к новому узлу (замыкание сетки за один хоп),
  по лучшему из названных им адресов. `node_leaving`: `note_left` СТРОГО после ретрансляции — он
  рвёт то соединение, по которому событие пришло (отмена читающей задачи оборвала бы рассылку).
- `make_link_factories` — единственный источник правды о создании линков, все шесть точек
  (в т.ч. `join`/`swarm_join`/`assign` в рантайме). Аудит 2026-07-28: линки, собранные на месте
  голым `PeerLink(...)`, не получали событий соседа (нет `on_event`) и не представлялись в auth
  (нет `self_node`). Локальным службам `self_node` не нужен.
- `restart_applied` (`_announce_version_if_changed`): версия сменилась с прошлого старта
  (`NodeState.last_known_version`). Молчит при первом старте с полем (иначе весь рой «применил
  обновление» после деплоя) и без смены. State персистится ДО доставки. Баг 2026-08-05:
  `emit` сразу после `server.start()` летит в пустоту (аутентифицированных соединений ещё нет);
  решение — повторять рассылку каждые `retry_s` в окне `window_s` фоновой задачей, пока не
  доставится хоть одному.
- `llm_went_idle` (не `llm_idle_sleep`): эмитится безусловно при естественном простое; запускает
  автовыключение (`NodeService.maybe_auto_poweroff_idle`). Находка 2026-08-03: с `llm_idle_sleep`
  автовыключение не срабатывало на машине, с которой Альфреду ни разу не писали.

## Presence (`node/watch.py`)
- Пропажа ноды, обязанной быть в сети (`always_on`), дольше `down_after_s` — `node_down`; возвращение
  после аварии — `node_up`. Пропажа рабочей станции — норма; но возвращение после любой
  недоступности (штатный уход, сон) объявляется информационно (`node_returned`, этап 23).
- Объявляет один: наименьший `node_id` среди живых (дедуп SeenEvents не спасает от трёх РАЗНЫХ
  событий об одной пропаже). Помечаем пропавшей независимо от того, объявляем ли мы (иначе после
  смены объявителя посыплются запоздалые дубли).
- Тип соседа сохраняется в состоянии ноды (`NodeState.remember_peer`, `PeerState.kind`):
  нужен, когда соседа уже не спросить.

## Discovery (`node/discovery.py`, этап 31)
- Broadcast по UDP на порт роя, ответ unicast. Даёт только КАНДИДАТОВ адресов; канал поднимается
  обычным TCP с auth по `[swarm].token`. Найденный сосед идёт в обычный `NodeService.join()`.
- Порт неотличим от закрытого: неверная подпись, чужая версия, мусор — дроп молча, без ответа и без
  INFO в логе. Подпись общим токеном над детерминированно сериализованным телом без `sig`.
- Версия формата датаграммы своя (не версия протокола v0). Потолок размера датаграммы; помнится
  несколько последних nonce (ответ спящей машины может прийти после следующего запроса); потолок
  адресов из ответа.
- Стучимся в порт РОЯ, не в свой локальный. Сети без вычисленного broadcast — ограниченный
  broadcast. Занятый порт маячка не мешает работать. Интервал запросов учащается, пока есть кого
  искать (нет пиров или хоть один недоступен); в штатном режиме маячок почти молчит.
- Broadcast не проходит через tailscale: ноды вне локалки — статикой или `[swarm].join`.
- `port` в конструкторе — только для тестов (0 = порт от ОС); в конфиге его нет.

## Транспорт (`proto/*`)
- NDJSON, одна строка UTF-8 JSON на сообщение, версия протокола в конверте. Unix-сокет доверяет
  правам файла (0600), TCP требует первым сообщением `auth {token}`; события только
  аутентифицированным.
- Адреса (`proto/endpoints.py`): ранги unix < приватная LAN < tailscale (CGNAT) < прочее. Собственный
  LAN доступен сразу после загрузки и не зависит от интернета — две машины в двух метрах обязаны
  видеться при лежащем провайдере. Виртуальные интерфейсы (vEthernet/WSL/Hyper-V, docker, br-,
  veth, virbr, vmnet) не объявляются: адрес хоста в NAT-сети контейнеров снаружи недостижим
  (деплой этапа 24: winpc объявил три таких, настоящий LAN оказался четвёртым в очереди).
  Loopback и `0.0.0.0` не объявляются; `0.0.0.0` раскрывается в адреса интерфейсов.
  `resolve_endpoint(..., base_dir)`: относительный unix-путь из чужого конфига — от каталога конфига.
- `ProtoServer.start`: если не поднялся НИ ОДИН адрес, ждать до `BIND_RETRY_TIMEOUT_S`; если хоть один
  есть — старт сразу, остальные добираются фоном (`_bind_later`, без дедлайна: tailscale может
  появиться через час). Находка 2026-07-28: на winpc tailscale отдаёт адрес через 40-60 с, WinSW
  сдавался после двух ретраев и ноды в рое не было. EADDRINUSE ждать бессмысленно.
- Живучесть: `SEND_TIMEOUT_S` на запись клиенту (полумёртвый клиент с забитым Send-Q блокировал
  рассылку и `emit` супервизора/аренды — head-of-line), `AUTH_TIMEOUT_S`, `CLOSE_TIMEOUT_S`
  (с Python 3.12 `wait_closed()` ждёт все обработчики; останов не должен зависеть от чужой воли).
  Рассылка параллельная. Каждый запрос — своя задача. Во время останова новые команды не
  принимаются (этап 29: нода приняла `restart_node` во время зависшего останова).
- TCP-опции (`proto/tcpopts.py`, обе стороны): keepalive (находка 2026-07-20) плюс
  `TCP_USER_TIMEOUT` (мс; находка 2026-07-28: keepalive не покрывает непустой Send-Q, ядро гоняет
  ретрансмиссии по tcp_retries2 ~15 минут — прод: `ESTAB 0 13720` к перезагрузившейся winpc,
  `PeerLink.alive` врал). Windows-аналог `TCP_MAXRT` (номер опции из mstcpip.h в Winsock, в
  `socket` констант нет). Принятым сервером сокетам keepalive тоже нужен (до v0.42 был только
  у клиентских).
- События клиента (`ProtoClient`) разбирает отдельная задача из очереди, по одному и в порядке
  прихода, а не цикл чтения. Порядок нужен: `task_prewake` открывает статус, `task_result` его
  закрывает. Находка 2026-10-18: обработчик в цикле чтения не мог дождаться ответа на собственный
  запрос по той же связи. `match_event` на `update_finished`/`restart_applied` падал по таймауту
  каждый раз с 08-04, подсказка «в другой стране работает» при исчерпанной квоте VPN не доходила
  с 10-10, а любой ответ ноды боту ждал, пока обработчик шлёт в Telegram. `join()` дожидается
  разбора очереди (последнее событие перед EOF, например `node_leaving`, не теряется), но не ждёт
  обработчик, погашенный через `abort`. `close()` и `abort()`, вызванные из самого обработчика
  (`note_left`), себя не отменяют.
- `Envelope.timeout_s` переживает форвард через все хопы; `hello` несёт `node_kind`, `wake`,
  `endpoints` (все необязательные — старые ноды их не присылают; WoL-реквизиты в hello с находки
  2026-07-27, раньше только в `get_state` и кэш у служб без истории опросов оставался пустым).
