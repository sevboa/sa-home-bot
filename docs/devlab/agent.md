# Агент-разработчик `devlab`

Этап 60, задача 60.5. Модель + обвязка, которые выполняют задание вида `agent`. Код: `devlab/agent/`.
60.5.1 (сделано) — цикл агента; 60.5.2 (сделано) — ветки агента, раздел «Git агента» ниже; он ничего не знает ни о хабе, ни о git, ни о Podman. Остальное
(ветки, контейнер, работник, вопросы владельцу, расход, слоты) — 60.5.2–60.5.7, см.
`IMPLEMENTATION_PLAN.md`.

## Состав
- `model.py` — `ChatModel` (`complete(messages, tools) -> ModelReply`) и `GatewayChat`:
  `POST <base_url>/v1/chat/completions` к шлюзу `devlab_models` без stream, с
  `Authorization: Bearer <токен исполнителя>` и `X-Devlab-Job: <id задания>` (по нему шлюз пишет
  расход). Токены `usage` возвращаются в `ModelReply`. Таймаут запроса `MODEL_TIMEOUT_S` = 30 мин
  (стенд 60.2: на CPU один запрос с большим окном идёт десятки минут). Любая беда транспорта и
  разбора — `ModelError`; тело ошибки шлюза (`{"error": ...}`) приводится к тексту.
- `sandbox.py` — интерфейс `Sandbox`: `read_bytes`, `write_bytes`, `list_files`,
  `exec(argv, timeout_s)`, `changed_paths()` (изменения относительно базы). Пути относительные,
  выход за корень — `SandboxPathError`. `LocalSandbox` на каталоге (тесты и отладка); контейнерная
  реализация — 60.5.3. `ExecResult.summary` режет вывод до конца (ошибки в конце) и помечает таймаут.
- `spec.py` — `AgentSpec`: команда тестов, `checks`, `allowed_commands`, `forbidden_paths`,
  `diff_prefixes`, таймауты, лимит вывода. Заполняется из `.devlab.toml` (60.5.3).
- `tools.py` — `ToolBox` и схемы: `list_files`, `read_file` (по строкам, ≤200 за вызов), `grep`,
  `edit_file` (один фрагмент, ровно одно вхождение), `write_file`, `run_command` (только
  разрешённые префиксы, без оболочки), `run_tests`, `finish`. Ошибка инструмента — `ToolError`,
  текст уходит модели. `forbidden_paths` закрывает запись (glob или префикс-каталог с `/`).
- `context.py` — окно. Оценка `len(json)/3` токенов. Перед каждым запросом, если диалог не влезает
  в `context_tokens - reply_tokens - схемы инструментов`, старые выводы инструментов (кроме
  `keep_recent` последних) заменяются на `[вывод свёрнут: N симв.]`, затем длинные аргументы
  старых вызовов (`write_file`). Системное сообщение и задание не сворачиваются. Не влезло и так —
  `CONTEXT_OVERFLOW`. По умолчанию окно 16000 (замер 60.2: больше 16k Flint на CPU деградирует).
- `guard.py` — `FinishGuard.verify()`: непустой дифф (в путях `diff_prefixes`, если заданы), затем
  тесты и каждый `check` в песочнице. Возвращает список причин отказа.
- `loop.py` — `AgentLoop.run(system, task) -> AgentResult`.

## Поведение цикла
- Закончить можно только вызовом `finish(summary)`; страж отклоняет без диффа и при красных
  тестах/стражах, текст отказа возвращается модели как результат инструмента, цикл продолжается.
- Ответ без вызова инструмента (в том числе «готово» текстом) не засчитывается: модели
  напоминают, после `max_idle_replies` подряд — `STUCK`.
- Ошибка инструмента (в том числе неожиданное исключение и невалидный JSON аргументов) не роняет
  цикл: модель получает `ошибка: ...`. `CancelledError` не глотается.
- `ModelError` завершает цикл `MODEL_FAILED` с причиной; повтор и смена модели решает вызывающий
  (60.5.4–60.5.6). Токены считаются по всем ответам, в `AgentResult`.
- Исходы: `FINISHED`, `STEP_LIMIT`, `MODEL_FAILED`, `CONTEXT_OVERFLOW`, `STUCK`.
- `on_change(описание)` — async-колбэк после `edit_file`, `write_file`, `run_command`; в 60.5.2 по нему
  делается коммит (репозиторий сам решает, чистое ли дерево).

## Шлюз
Исполнитель ходит в шлюз тем же токеном `executor`, что и в хаб (шлюз проверяет его через
introspect). Адрес шлюза выбранной модели в каталоге хаба пока не отдаётся исполнителю: в 60.5.1
`GatewayChat` получает `base_url` снаружи, выбор шлюза — 60.5.6.

## Тесты
`tests/unit/test_devlab_agent.py`: скриптованная модель `ScriptedChatModel` и `tool_reply` из
`tests/unit/support/fakes.py`; `GatewayChat` проверяется на локальном aiohttp-сервере (заголовки,
usage, таймаут, HTTP-ошибка).

## Git агента (60.5.2)
`repo.py`, `AgentRepo` поверх `ProjectMirror` (общий `GitRunner` из `executor/mirror.py`: токен
только в окружении `GIT_CONFIG_*`, из ошибок вырезается). Ветки: `base/<id>` (снимок клиента) →
`wip/<id>` (ход работы) → `agent/<id>` (итог). Репозиторий рабочей копии лежит отдельно от неё
(`git_dir` рядом с `workdir`), так что в каталог, который уйдёт в контейнер, `.git` не попадает.
- `open()`: fetch зеркала; если `wip/<id>` на хабе есть, рабочая копия встаёт на его вершину,
  иначе на `base/<id>`. Если локальная копия уже впереди вершины хаба (не успели запушить до
  рестарта), она сохраняется, а не затирается; хвост уйдёт следующим push.
- `on_change(описание)` подключается к `AgentLoop`: `git add -A`, пустые изменения не коммитятся,
  тема коммита — описание действия. Автор настраивается: `CommitAuthor`, по умолчанию
  `agent_author(модель)` = `devlab-agent (<модель>)`.
- Склейка push: не чаще раза в `push_interval_s` (30 с). Первое изменение уходит сразу, дальнейшие
  копятся и уходят таймером, который выставляется на остаток интервала; неудавшийся push не
  роняет цикл (лог, повтор по таймеру/`flush()`). `milestone(название)` (для `step_done`) и
  `finish`/`abandon` пушат всегда и с ошибкой, если не вышло.
- `milestone`: коммит `веха: <название>` (допускается пустой: веха фиксирует шаг даже без правок).
- `finish(резюме)`: докоммитить хвост, push `wip`, squash одним коммитом на `base/<id>` с деревом
  `wip` (сообщение: резюме, id задания, автор, список вех), push `+agent/<id>`, удаление
  `wip/<id>` на хабе и локального репозитория. Каталог `workdir` не трогается.
- `abandon(причина)` для `failed`/`stopped`: то же, но сообщение `не завершено: <причина>`; если
  правок относительно базы нет, `agent/<id>` не создаётся. Клиенту остаётся видимым `agent/<id>`
  с частичным результатом (если он есть); `wip/<id>` не остаётся никогда.
- Права: пушатся только `wip/<id>` (создать/обновить/удалить) и `agent/<id>` (создать/обновить),
  всё в рамках `refpolicy` для роли `executor`.
- Тесты: `tests/unit/test_devlab_agent_repo.py` (настоящие git и хаб).
