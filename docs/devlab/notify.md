# Оповещения владельцу о заданиях агентов (Этап 62.2)

Бот (`bot/devlab_notify.py::DevlabNotifier`) раз в `poll_s` смотрит ящик хаба всех клиентов
действием `owner_inbox` (proto, `Address(hub_node, devlab_hub)`) и шлёт админам сообщения о
заданиях агентов. Выключено по умолчанию: `[devlab_notify] enabled = false`, задача не стартует.
Поля конфига: `docs/platform/config-reference.md` (`DevlabNotifyConfig`).

## Курсор
- `app_state["devlab_inbox_cursor"]` — seq последнего обработанного сообщения.
- Нет курсора: `owner_inbox since=-1`, записывается текущий максимум seq, историю не шлём.
- На каждое сообщение: отправка, затем запись курсора. Сообщение, пропущенное фильтром, тоже
  двигает курсор. Дубль возможен только при падении между отправкой и записью курсора.
- Хаб недоступен (`UNREACHABLE_ERRORS`): запись в лог, курсор не двигается, повтор на следующем проходе.

## Фильтр
Оповещаются только задания `kind == agent` и сообщения `question`, `done`, `failed`, `stalled`.
`question` пропускается, если задание уже не `waiting_owner` (ответили по MCP); `stalled` — если
задание уже не `running` (дошло, остановили). `test_done`,
`started`, `step_done`, `stopped` не шлются.

## Текст
Вступление-заглушка (`bot/ai_lines.py`: `DEVLAB_QUESTION_TEXT`, `DEVLAB_DONE_TEXT`,
`DEVLAB_FAILED_TEXT`) и блок фактов: проект, номер, заголовок, модель, токены и $, ветка
`agent/<id>`, текст вопроса / сводка / причина провала. Всё через `html.escape`, тело обрезается
`facts_max_chars`.

## «Работа встала» (Этап 62.6, 2026-11-02)
Сообщение `stalled` кладёт хаб (`docs/devlab/queue.md`, «Застой»). Текст по образцу `failed`:
заглушка `DEVLAB_STALLED_TEXT` и факты:
проект, номер, заголовок, модель, токены, ветка, «Без вестей: N мин», «Исполнитель: на связи /
не отвечает». Кнопка одна: «Остановить» (`stopw`) → «Точно остановить?» (`stopc`) / «Отмена» (`cnlw`,
возвращает кнопку «Остановить»; свои коды, чтобы отмена не показывала кнопки `question`).
MCP-клиент видит `stalled` в `devlab_inbox` как обычное сообщение ящика.

## Вступление (2026-11-18)
Вступление — всегда готовая строка из `bot/ai_lines.py` (словарь `LEADS` в
`bot/devlab_notify.py`), служба `llm` не вызывается. Раньше `_compose_lead` звал `chat`
(поднятие большой модели на машине с видеокартой и вытеснение модели разработки), вызов убран
вместе с `llm_timeout_s`, `LEAD_INSTRUCTION`/`LEAD_EVENTS` и обрезкой ответа.

## Доставка
Каждому админу (`WILDCARD in allowed_commands`) `Notifier.send_direct(outbox_kind=task,
dedup_key="devlab:<seq>")`: при временном сбое Telegram сообщение уходит в outbox.
`broadcast` не подходит: возвращает число доставок, а не `message_id`.

## Кнопки (Этап 62.3)
`bot/handlers/devlab.py`, роутер включён сразу после `away`, ловит только callback `dl:`.
Каждое нажатие проверяет `subscription.is_owner` и `from_user.id == subscription.chat_id` (не одно
`allows_action`); чужим `DENIED_ALERT_TEXT`.
- Кнопки (`bot/devlab_notify.py`, `callback_data = dl:<код>:<job_id>`): `question` — «Отпустить
  спать» (`rel`), «Остановить» (`stop`); `failed` — «Продолжить» (`res`); `done` без кнопок.
- `stop` не шлёт ничего, а меняет клавиатуру на «Точно остановить?» (`stopc`) и «Отмена» (`cnl`,
  возвращает клавиатуру вопроса). `rel`/`stopc`/`res` → `owner_post id kind`; успех: toast со
  статусом, клавиатура снята, `DevlabNotifier.kick()` (если опрос включён). Отказ хаба
  (`bad_request`): toast с текстом, клавиатура снята. Хаб недоступен: toast, клавиатура остаётся.
- В оповещении `question` последней строкой `DEVLAB_ANSWER_HINT`: ответить агенту можно через
  Claude (`devlab_answer` по MCP).
- Старые кнопки «Ответить» (`dl:ans:…`) в уже отправленных сообщениях: нажатие просто гасит
  часики, ничего не делает.

## Ответ агенту из Telegram убран (решение владельца 2026-11-02, 62.3.1)
Кнопка «Ответить», ForceReply-подсказка, `DevlabReplyFilter` и ключи `app_state`
`devlab_notice:*`/`devlab_reply:*` удалены. Реплай владельца на оповещение идёт в обычный диалог с
Альфредом. Отвечать агенту — через Claude (`devlab_answer`); позже прямой диалог с агентами
переедет в отдельный Telegram-бот мастерской. `owner_post` хаба не менялся, `kind=answer` из бота
просто больше не шлётся. Оставшиеся на проде ключи `devlab_notice:*`/`devlab_reply:*`
`DevlabNotifier.run` один раз сносит при старте (`purge_legacy_keys`); убрать вместе с
константой `LEGACY_STATE_PREFIXES`, когда выкат пройдёт.

Урок 2026-11-02: в проде реплай «go» на подсказку ушёл Альфреду, а не в хаб.
`AuthorizationMiddleware` висит inner-middleware на `dp.message`, а aiogram зовёт фильтры роутера ДО
inner-middleware, поэтому `subscription` в фильтре всегда была `None`, и фильтр молча отвечал False
(юнит-тесты передавали `subscription` руками). Фильтру видны только workflow-данные
`start_polling` (`store`, `book`, …) и то, что кладут outer-middleware. Кнопки не страдали: их фильтр
только `F.data`, а `subscription` получает уже хендлер. Страж для такого класса ошибок —
`tests/unit/test_devlab_dispatch.py`: апдейты идут через настоящий `build_dispatcher` +
`feed_update` с workflow-данными как в `app.py`.

## Список заданий (2026-11-19)
Действие хаба `owner_jobs` (proto, `ACTION_OWNER_JOBS`, параметры `offset`/`limit`, оба
необязательные) показывает владельцу активные задания страницами. Порядок: задания `running` и
`waiting_owner` первыми (по `started`, затем `seq`), за ними `queued` в порядке, в котором их
возьмёт исполнитель (`QUEUE_ORDER_SQL` хаба: тесты раньше агентов, fix → dev → bench, дальше
priority и seq). Ответ: `jobs` (виды как в `owner_job`, с заголовком), `total` — общее число
активных, `offset`. Пределы: `offset` не меньше 0, `limit` по умолчанию 20, от 1 до 50
(`OWNER_JOBS_MAX_LIMIT = 50`); вне пределов — `bad_request`. Метод хаба —
`queue.active_jobs(offset, limit)`.

### Поля задания (2026-11-19)
Каждый объект в `jobs` и ответ `owner_job` теперь содержат дополнительные поля:
- `steps` (int) — количество сообщений `step_done` у задания, 0 если шагов нет.
- `last_step` (string) — текст последнего шага (`payload.text` от `step_done`), обрезанный до
  200 символов; пустая строка, если шагов нет.
- `deps` (array) — список зависимостей из `params.depends_on`; каждый элемент — объект
  `{"id": "<job_id>", "status": "<status>"}`. Пустой массив, если зависимостей нет.

## Экран /jobs (2026-11-19)
Экран команды `/jobs` строится в `bot/devlab_jobs_view.py`. Используется rich-сообщение
(Bot API 10.3+, aiogram 3.32, `InputRichMessage(html=...)`).

Страница заданий: заголовок с общим числом активных и номером страницы, затем строки,
сгруппированные в разделы: «🟢 Идут» (running), «❓ Ждут ответа» (waiting_owner),
«⏳ Очередь» (queued). Пустые разделы не выводятся. В заголовке страницы показаны счётчики
по всем активным: `🟢N ❓N ⏳N`. Нумерация строк сквозная по разделам.

Строка задания: номер — кликабельная ссылка внутри текста:
`<tg-button type="callback_data" style="link" data="dj:c:<id>:<offset>">id</tg-button>`.
После типа: возраст (`· 4м`, `· 3 ч 5 мин`, `· 2 д 4 ч`), для running — шаг (`· шаг 3`),
если есть зависимость не в done — первая такая (`· ⛓ job-5`), роль профиля, если задана и
не `executor` (`· docs`). Нажатие открывает карточку задания.

Карточка задания: абзацы с полями:
- id, тип, статус, проект, заголовок, модель
- «Основа: base/…» (если есть `params.depends_on`)
- «Ветка: agent/<id>»
- «Роль: <profile>» (если не `executor`)
- «Зависимости: id (статус), …» (если есть `deps`)
- «Идёт {возраст}» для running/waiting_owner, «В очереди {возраст}» для queued
- «Запасная модель: <fallback>» (если есть `params.fallback`)
- «Взята вместо: <original_model>» (если есть `params.original_model`)
- «Создано / начато» в формате UTC
- «Токены: N»
- «Последний шаг ({steps}): <last_step>» (если `steps > 0`)
- вопрос (если есть)

Клавиатура под сообщением: «📄 Задача» → `dj:t:<job_id>`,
«⬅️ К списку» → `dj:p:<offset>`, «⏮ В начало» → `dj:p:0` (только при `offset > 0`),
«🔄 Обновить» → `dj:c:<id>:<offset>`.

Callback-схема:
- `dj:p:<offset>` — страница списка;
- `dj:c:<job_id>:<offset>` — карточка задания (offset нужен для возврата на ту же страницу);
- `dj:t:<job_id>` — запрос текста задачи файлом, действие хаба `owner_task` (`ACTION_OWNER_TASK`,
  параметр `id`), ответ — документ `task-<id>.md` с полным текстом задачи, карточка не меняется.

Все пользовательские данные экранируются `html.escape` (в атрибуте `data` — с `quote=True`).
Длина каждого `callback_data` не превышает 64 байт.

Пагинация: страница по 20 заданий (`PAGE_SIZE`). Если HTML превышает 4096 символов
(`TEXT_LIMIT`) — автоматически переключается на 10 заданий (`SMALL_PAGE_SIZE`).
Навигация под сообщением: обычные кнопки `nav_row` (⬅️/➡️) и «🔄 Обновить».

## Ждёт слот (2026-11-20)
После ответа владельца хаб сразу ставит заданию `running`, но исполнитель продолжает его только
когда освободится слот. Пока слот занят, задание висит «🟢 идёт», хотя стоит. Нужно отличать такие
задания: хаб помечает их полем `slot_wait`, а бот показывает значок 📌 («ответ получен, идёт следующим»).

**Признак**: задание `running`, вида `agent`, и у него есть сообщение `MSG_ANSWER` в сторону исполнителя
(`DIRECTION_TO_EXECUTOR`), после которого (больший `seq`) нет сообщения `MSG_STARTED` в сторону клиента
(`DIRECTION_TO_CLIENT`). Продолжение после ответа всегда шлёт `started`, поэтому признак снимается сам.

**Реализация**:
- `protocol.FIELD_SLOT_WAIT = "slot_wait"` — поле в протоколе.
- `HubQueue.slot_waiting(job_ids)` — SQL-запрос, возвращающий id заданий, ожидающих слот.
- `HubService._owner_views` вызывает `slot_waiting` для running-заданий вида agent и кладёт
  `slot_wait` в каждый view.
- `bot/devlab_jobs_view.py`: константы `SLOT_WAIT_ICON = "📌"`, `SLOT_WAIT_TEXT = "ждёт слот"`.
  В `job_line` и `render_card` для running с `slot_wait` значок 📌 вместо 🟢 и пометка
  `· ждёт слот` после возраста. Отдельную секцию не заводим: задание остаётся в «Идут»,
  но в счётчике шапки считается отдельно: `(🟢N 📌M ❓K ⏳L)`, 📌 показывать только если M > 0.

## Кнопки действий карточки (2026-11-20)
Карточка задания в /jobs получила ряд действий перед навигацией (коды `dj:s|S|r|u`, формат
`dj:<код>:<job_id>:<offset>`): `running` — «Остановить»; `waiting_owner` — «Отпустить» и
«Остановить»; `stopped`/`failed` — «Продолжить»; у остальных статусов ряд не выводится.
«Остановить» сначала перерисовывает карточку с подтверждением («Точно остановить?» → `S`,
«Отмена» → обычная карточка), ничего не шлёт хабу. `S`/`r`/`u` → `owner_post` с `MSG_STOP` /
`MSG_RELEASE` / `MSG_RESUME` (свод `POST_KINDS` в `bot/handlers/devlab.py`), тост
`DEVLAB_POSTED_TOAST`, `DevlabNotifier.kick()`, затем заново `owner_job` и перерисовка карточки;
ошибка хаба — alert, карточка не меняется. Коды не пересекаются с кнопками оповещений (`dl:`).
