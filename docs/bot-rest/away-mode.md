# Режим «Альфред в городе» (этап 51)

Модули: `bot/away.py`, `bot/away_return.py`, `bot/handlers/away.py`, `away_cli.py` (чужая зона).

Назначение: на время обслуживания или занятия mycraft (обновления, датасет, обучение LoRA) никто не должен звать модель. Альфред «спустился из замка в город»: входящее копится в `ai_turns`, модель не зовётся, гостям уходит заготовленная записка (без LLM); по возвращении он разбирает всё сам.

## Состояние

Одна запись `app_state["alfred_away"]` (JSON, `AwayState`) — формат и ключи менять нельзя. Читается из БД на каждом входящем, поэтому правка из CLI (`sa-home-bot away …`) подхватывается без рестарта. Таймеров в памяти нет: срок и потолок проверяет проход `AwayRunner` раз в минуту; состояние переживает рестарт. Повреждённая запись == «Альфред дома» (испорченное состояние не должно навсегда заглушить бота).

Поля: `noted` — когда последний раз писали записку гостю (по chat_id, ключи JSON строками); `pending` — что нужно для ответа при возвращении; `reminded_for` — для какого `until` уже отправлено напоминание за 15 минут (после продления напомним заново); `attempts` — сколько раз подряд не вышло ответить чату при возвращении.

## Фазы и сроки

- `away` — в городе. `returning` — возвращение объявлено (`/back`, кнопка, потолок), очередь не разобрана: гости видят «вот-вот вернётся», модель не зовётся ни для кого, кроме разбора очереди. Запись исчезает, когда `pending` пуст.
- Потолок: не позже 24 ч от `started_at`; продления за потолок не уводят (уже на нём — `AwayError`). По `until` режим НЕ снимается — Альфред «задерживается» до `/back`.
- Срок: `3ч`, `1ч30м`, `90 минут`, `1.5h`; `до 23:00` (ближайшее такое время в поясе, прошло — завтра); `завтра 10:00`. Число без единицы — не срок. Записка гостю не чаще раза в N минут на чат, после продления — заново.
- «Замковые часы» — `Europe/Bucharest` (`castle_clock`, = ALFRED_TIMEZONE); не менять.
- `AwayService` без `notifier`/`book` (CLI — отдельный процесс) умеет только править запись; сообщения владельцу от CLI кладутся в очередь `queue_notice`, их шлёт бот.
- Модуль не импортирует хендлеры на уровне модуля (они импортируют его).

## Перехват (`AwayService.intercept`)

True — Альфред в городе: входящее записано в `ai_turns`, записка (если пора) отправлена, вызывающий выходит. За время отъезда все входящие чата сводятся в один диалог (тот, что открыл первый перехват). Файлы (голосовое/кружок/аудио) качаются сразу (потом могут быть недоступны) в `away-media` рядом с БД (eMMC alfred, не `/mnt/scratch`); не вышло — остаётся `file_id`. В `ai_turns` на месте файла стоит заглушка до распознавания.

## Возвращение (`AwayReturn`)

1. Ждём готовности LLM на mycraft (`wake_core.ensure_service_ready`); пока нет — гости видят «вот-вот вернётся», следующий проход повторит.
2. Чаты из `pending` — строго по одному (у Ollama одна очередь).
3. В чате: отложенные голосовые по порядку через `voice_stt` (транскрипт подменяет заглушку), затем ОДИН запрос к Альфреду через обычный `_ask_and_reply` с system-вставкой «ты вернулся из города»; ответ реплаем на последнее сообщение.
4. Чат снимается с очереди только после доставленного ответа. Пока шёл ответ, в чат могли написать ещё — тогда он остаётся на следующий круг. Состояние в БД, поэтому падение продолжается с места остановки.

`record_failure`: после N подряд неудач чат снимается, владельцу — сообщение. Лимит голосовых при возвращении — на чат.
