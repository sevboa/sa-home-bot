# Получатели личных сообщений (`bot/recipients.py`)

Задача: превратить то, как человека назвали («передай Андрею», «скажи @andrey»), в `chat_id` личного чата (тул `tell`). Имена знает карточка (`people/book.py::PeopleBook`, этап 58): имя, прозвища, профиль Telegram, @ник, имя при приглашении; без карточек (служба tasks) — имена подписок.

Жёсткие ограничения:
1. Только подписной чат: нет подписки — нет получателя, даже при совпадении с карточкой.
2. Только личка (`chat_id > 0`, равен `user_id`); групповые чаты в кандидаты не попадают.

Правило: неоднозначность не разрешается догадками — возвращаются все кандидаты, спрашивает Альфред. «Лучше не угадать, чем написать не тому»: `matches("андрюха", "Андрей Иванов")` намеренно ложь.

Приоритет: явный id или «@ник» сильнее имени (не склоняются и не переиначиваются моделью); затем роль владельца (`SOURCE_OWNER_ROLE`, стебли «хозя», «владел», «админ», «граф», «собственник», «owner», «admin» — первой, чтобы «передай владельцу» всегда давало эту роль; tell пускает к владельцу без знакомства только по роли); затем имя (целиком, по слову или по началу слова).

Живые баги:
- 2026-08-01: `invited_user` выглядит как «Имя Фамилия (@username)»; слово «(@username)» не начиналось с «username», и голый юзернейм не находил человека. Скобки и «@» разбираются.
- 2026-09-27: «Алексей Севбо» не находил «Алексей Александрович Севбо» — теперь каждое слово запроса должно быть началом своего слова кандидата, порядок не важен.
- 2026-09-27: модель передавала адресата целым лейблом «Наталья (@nava40a)», успев переиначить имя; если ник назван — ищем только по нему, а если ник не наш (сменил) — пробуем имя без скобки.
- Явный «id 123…» — любой длины; голое число короче пяти цифр — не id.

Формулировки склонения в `people_cards.py` — персонажный текст, не трогать.
