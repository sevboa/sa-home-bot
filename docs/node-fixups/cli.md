# `nodectl` и `sa-home-bot init`

## nodectl
Локальная консоль ноды, подключается к endpoint'у службы ноды по протоколу v0.

| Команда | Что делает |
|---|---|
| `status` | нода и её службы |
| `start|stop|restart X` | управление службой |
| `restart_node` | перезапустить саму ноду (не службу) |
| `poweroff|reboot|suspend` | питание машины |
| `events` | живой хвост событий (Ctrl+C — выход) |
| `fix` | доустановить/донастроить права на месте ([fixups.md](fixups.md)) — не ходит по протоколу, работает локально |
| `restore-stage|restore-apply|backup-release` | восстановление vpn-сервера из бэкапа напарника (39.0.8(d)); тоже локальные |
| `check_update`, `update` | версии; `pipx install --force` до последнего тега, процесс НЕ перезапускается — `restart_node` потом делает человек |
| `-n winpc status` | то же о другой ноде («спроси любого»: запрос идёт своей ноде, та пересылает) |
| `describe <служба>`, `call <служба> <действие> ключ=значение` | любое умение любой службы роя тем же путём, что Альфред (`bot/tools.py`); ответ — JSON |

Endpoint: `--socket` (путь unix-сокета или `tcp://host:port`), либо `[node].socket` указанного
`--config`, либо первый найденный конфиг (`./config.toml`, потом `~/.config/sa-home-bot/config.toml`),
либо `./data/node.sock`. Токен для tcp — `[swarm].token`. Относительный сокет в конфиге
резолвится от каталога конфига, а не от CWD (`nodectl -c ~/proj/config.toml status` работает откуда
угодно).

`call --timeout`: долгие умения (llm warmup/ask грузят модель — на 35B это минуты) с дефолтом в 10 с
проверить было нельзя — консоль отвечала «нода не ответила вовремя», хотя служба работала
(разбор 2026-07-30). Действия без параметров (`NO_ARG_ACTIONS`) объявляются динамически: нода может
не поддерживать (напр. `restart_node` без колбэка) — тогда сервер вернёт `unknown_action`.
Значения `ключ=значение` распознаются по виду (true/false/int/float): протокол разрешает только
string|int|float|bool, а из командной строки всё приходит строкой; значение может содержать «=»
(magnet-ссылки) — режем по первому.

### Рабочий каталог ноды
Локальные команды, которые трогают данные ноды (`restore-*`, `backup-release`), выполняются из
`NODE_WORKDIR` (`~/.local/share/sa-home-bot` = `WorkingDirectory` юнита ноды): относительные пути
конфига (`./data/node-state.json`, `[vpn].db_path`) резолвятся от него, иначе маркер публикации
бэкапа и бандл восстановления уезжают в `~/data`. Относительный `--config` резолвится от места
запуска ДО смены каталога. Бандл восстановления принимается со stdin и пишется `0600`; после
применения удаляется (на диске приватные ключи).

## sa-home-bot init (setup_wizard)
Установка новой ноды без git-checkout: раньше нужно было клонировать репозиторий за
`config.example.toml` и `deploy/sa-home-node.service` и вручную править id/kind/token/join и
абсолютные пути. Команда пишет минимальный `config.toml` (`[node]`/`[swarm]` и абсолютные пути
служб; остальное — дефолты `config.py`) и на Linux user-юнит systemd. Работает интерактивно и
флагами (`--non-interactive` — установка по SSH одной командой, спросить не у кого).

- **Сокеты и БД абсолютные** внутри `data_dir`: `nodectl` резолвит относительные пути от каталога
  config.toml, а сервис — от своего WorkingDirectory; при обычной установке (конфиг в `~/.config`,
  данные в `~/.local/share`) `nodectl status` не находил сокет — живой баг 2026-08-01, mycraft.
- **Пустой `listen` = нельзя вступить в рой**: `swarm_join` на принимающей стороне требует наш
  endpoint (`node/service.py::_swarm_join`, `ERR_BAD_REQUEST` без него), а взять его неоткуда без
  хотя бы одного слушаемого TCP-адреса — живой баг 2026-08-01 на mycraft. Для server/workstation
  дефолт `tcp://0.0.0.0:8710`; для vps (публичный IP) 0.0.0.0 давать нельзя — нужен явный
  приватный/tailscale-адрес, иначе рой торчит в интернет.
- **Пустой `join` не значит «нода первая»**: если рой уже есть в этой LAN, маячок
  (`node/discovery.py`) сам найдёт и присоединится при совпадении `[swarm].token`. Поэтому «основываем
  новый рой» решается отдельным вопросом, и токен генерируется только в этом случае.
- **PATH юнита**: `~/.local/bin` первым — не `Path(exec_path).parent` (при pipx `exec_path` может
  резолвиться до каталога venv, где обёртки smartctl нет); обёртка всегда лежит в
  `SMARTCTL_WRAPPER_PATH.parent`.
- Сразу после записи конфига мастер зовёт те же фиксы, что `nodectl fix`; не в интерактивном режиме
  (sudo спросить не у кого) только печатает подсказку. `loginctl enable-linger` — тоже через sudo
  только интерактивно.
