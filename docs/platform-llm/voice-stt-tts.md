# Голос: STT и TTS

Оба модуля живут в службе llm, а не в боте: alfred шлёт сырые байты (или текст), нода с большим CPU обрабатывает. Это CPU/RAM, не GPU и не Ollama: VRAM Tesla V100 занята моделью персонажа почти под завязку.

Тяжёлая модель в обоих модулях резидентна с первого запроса до конца жизни процесса (`LazyModel`, `llm/lazy_load.py`): конкуренции за VRAM нет, незачем выгружать между запросами. Библиотеки (`faster-whisper`, `coqui-tts`) — экстры `stt`/`tts`, поэтому импортируются лениво внутри `_load_model_sync`, и служба импортируется на нодах без экстр.

## STT (`llm/stt.py`)

faster-whisper на CPU. Находка при выборе архитектуры (2026-08-10): аудио-вход самой Gemma 4 (`gemma4:e2b`/`e4b`) через Ollama на практике сломан (галлюцинации, минуты на секунды аудио, открытые баги апстрима), а продовая `gemma-4-26B-A4B` аудио не поддерживает; второй модели в VRAM места нет без выгрузки первой.

- Модель `medium` занимает ~1.5 ГБ RAM, при 62 ГБ на mycraft это не заметно.
- faster-whisper сам декодирует и режет на окна, VAD отсекает тишину: произвольная длина входа без ручной нарезки на 30-секундные куски.
- Запись временного файла, инференс и удаление делаются одним куском в потоке (`_write_transcribe_cleanup_sync`), чтобы не блокировать цикл службы.
- Пустая строка — не ошибка (тишина/неразборчиво); как показать это пользователю, решает `llm/service.py`.

## TTS (`llm/tts.py`)

Coqui XTTS v2: voice cloning по одному референсному WAV (`LlmConfig.tts_reference_voice_path`), а не набор фиксированных дикторов. Картавость персонажа сюда не относится: она вшита подменой букв в текст до синтеза, синтезатор читает уже подменённые буквы.

- Находка 2026-08-11 (деплой, логи mycraft): наивный `tts_to_file(..., speaker_wav=путь)` пересчитывает conditioning latents ЗАНОВО НА КАЖДОЕ предложение (coqui-tts бьёт текст на предложения); для ответа из 5 предложений 58 из 77 секунд уходили на повторный пересчёт одного и того же голоса. Латенты считаются один раз при загрузке модели и кладутся в `speaker_manager.speakers[_SPEAKER_ID]` через `_VoiceCache` (подмена `SpeakerManager` той же формы, но без чтения `speakers_xtts.pth`), дальше синтез идёт с `speaker=_SPEAKER_ID`. Латенты хранятся внутри резидентной модели, не отдельной переменной, чтобы не рассинхронизироваться с файлом, для которого посчитаны.
- Цена: смена референсного файла на лету больше не подхватывается, нужен перезапуск службы.
- XTTS отдаёт только WAV, а Telegram `sendVoice` требует OGG/Opus: конвертация внешним `ffmpeg` (`apt install ffmpeg` на ноде, разовый инфраструктурный шаг вне extras). Код ffmpeg != 0 превращается в `RuntimeError` с stderr.
- Временные wav/ogg удаляются в любом случае, даже при сбое ffmpeg.
- Ошибки (нет референса, модель не загрузилась, ffmpeg упал) пробрасываются исключением; `llm/service.py` превращает их в `ProtoError`, а `bot/voice_tts.py` откатывается на текстовый ответ.
- Лицензия CPML (некоммерческая): первая загрузка весов требует явного согласия оператора через `COQUI_TOS_AGREED=1` в юните службы. Молча соглашаться с лицензией от имени пользователя код не должен.
- Пины зависимостей (torch, numpy, transformers) — в `docs/deploy` и `pyproject.toml`, в этой зоне их не трогаем.
