# Маршрутизатор моделей Strata (`llm/strata_switch.py`)

## Зачем

На mycraft одна видеокарта, и Strata держит в памяти одну модель: сменить её можно только
перезапуском. Скрипт запуска (например `/models/sa-home/stand/iq3-on.sh`) сам останавливает
старую модель и выходит с кодом 0, когда новая готова отвечать; запуск длится 1–2 минуты.

Маршрутизатор (`python -m sa_home_bot.llm.strata_switch`, по умолчанию `127.0.0.1:8090`) стоит
перед Strata и делает поле `model` в запросе выбором модели: сам дёргает нужный скрипт запуска и
проксирует запрос в Strata (`http://127.0.0.1:8080`). Клиенты — шлюз devlab и Open WebUI; обе уже
присылают `Authorization` с ключом Strata, поэтому маршрутизатор пересылает заголовок как есть,
ключей не хранит и не логирует.

## Правило переключения

- `acquire(model)` для уже загруженной модели ничего не перезапускает.
- Смена модели идёт под блокировкой: сначала ждём, пока счётчик запросов в работе станет нулевым
  и с конца последнего запроса пройдёт `idle_s` (по умолчанию 300 с). Пока текущей моделью
  пользуются, другую не запускаем.
- Быстрый путь «модель уже загружена» работает только когда переключения нет. Иначе запрос к
  старой модели ждёт блокировку: скрипт запуска уже погасил Strata, и пропустить запрос к старой
  модели означало бы отдать ей битовый ответ об ошибке. Во время переключения все запросы ждут.
- Не дождались за `max_wait_s` (по умолчанию 1800 с) — `SwitchBusy`, клиенту 503.
- Код выхода скрипта не 0 — `current` сбрасывается, `LaunchFailed`, клиенту 502.
- `GET /v1/models` список моделей отдаёт по ключам `launchers` и `aliases` и в Strata не ходит:
  Open WebUI зовёт его при выборе модели в списке, переключение должно случаться только на
  настоящем запросе к чату.
- К запросу в Strata сессия создаётся с `UPSTREAM_TIMEOUT`: `total=None`, `sock_read=None`,
  `sock_connect=15` (`UPSTREAM_CONNECT_S`). Таймаута на чтение ответа нет намеренно: локальная
  модель без потока отвечает до 15 минут, а devlab ждёт 900 с; дефолтные 300 с aiohttp рвали
  такой ответ на середине.

## Псевдонимы и приоритетные запросы

### Зачем

На одной Strata работают и агенты devlab (долгие запросы по 5–15 минут), и Альфред (короткий ответ
нужен сразу). Без правил Альфред ждёт конца агентского запроса: очередь к Strata одна. Правило
такое: запрос к приоритетному имени модели обрывает текущие обычные запросы и выполняется сразу;
обычные дожидаются окончания приоритетных и повторяются сами. Клиент обычного запроса ошибки не
видит — только более долгий ответ. Strata держит разобранный контекст в кэше, поэтому повтор
дешёвый (находка 2026-11-14: проверено на маршрутизаторе с фейковым upstream, повтор обычного
запроса укладывается в доли секунды после конца приоритетного).

### Псевдонимы

`[aliases]` даёт имени в `launchers` второе имя, которым его зовут клиенты: `alfred = "qwen3.8-iq3_xxs"`.
`load_settings` проверяет, что псевдоним ведёт к имени из `launchers`, иначе `UnknownModel` при
загрузке конфига. `resolve(model)` возвращает имя из `launchers` для имени или псевдонима; `POST`
проверяет модель через `resolve` и дальше работает настоящим именем (в `acquire` и в upstream
уходит имя из `launchers`). `GET /v1/models` отдаёт и `launchers`, и псевдонимы — Open WebUI и
шлюз devlab могут звать модель по короткому имени.

### Приоритет

`priority = ["alfred"]` — список имён (своих или псевдонимов), запрос к которым идёт вне очереди.
Ворота `PriorityGate` устроены так:

- `enter_priority()` — приоритетный запрос входит: помечает все обычные попытки обрываемыми и
  отменяет их задачи (отменa закрывает aiohttp-сессию, и Strata перестаёт работать над запросом:
  upstream видит обрыв); затем ждёт, пока обычные попытки действительно завершатся, и пока
  неотменяемые потоки (см. ниже) не закончатся.
- `leave_priority()` — снимает счётчик и запоминает время конца.
- `wait_normal()` — обычный запрос ждёт, пока нет активных приоритетных и с конца последнего
  приоритетного не прошло `priority_grace_s`; проверка каждые `poll_s`, верхнего предела нет.

Обычный запрос в обработчике идёт циклом: `wait_normal` → пересылка отдельной задачей,
зарегистрированной как обрываемая → ожидание. Если задачу оборвали ворота (а не клиент), цикл
повторяет то же тело запроса; если отменил клиент — ответ не повторяется.

Исключение: потоковый обычный запрос (`stream: true`) обрываем, только пока клиенту не ушло ни
одного байта. Ответ клиенту готовится после первого байта от upstream, поэтому до первых байтов
повтор ещё возможен и не оставляет клиенту «надорванного» ответа. После первого записанного байта
поток снимается с регистрации и доживает до конца, а приоритетный запрос ждёт его окончания
(счётчик неотменяемых активных потоков).

Приоритетный запрос: `enter_priority` → `acquire` → пересылка → `release` и `leave_priority` в
`finally`. Смена модели для приоритетного запроса не ждёт простоя `idle_s`: переключение начинается
сразу, как только нет активных запросов (обычные оборваны, потоки дожиданы). Обычные запросы
переключаются по-прежнему по `idle_s` — он нужен, чтобы не гонять модели туда-сюда под нагрузкой;
`priority_grace_s` держит только паузу после приоритетного ответа, чтобы Альфред не встал в очередь
за только что оборванным агентом.

### TOML

```toml
default = "iq3"
idle_s = 300.0
max_wait_s = 1800.0
priority_grace_s = 10.0
priority = ["alfred"]

[aliases]
alfred = "qw2"

[launchers]
iq3 = ["/models/sa-home/stand/iq3-on.sh"]
qw2 = ["/models/sa-home/stand/qw2-on.sh"]
```

`[aliases]`, `priority` и `priority_grace_s` необязательны; без них поведение прежнее (обычные
запросы не обрываются, псевдонимов нет). Имя из `priority` должно быть среди `launchers` или
`aliases`, иначе `UnknownModel` при загрузке конфига.

## Компаньон

### Зачем

Альфред переезжает на Gemma: она живёт в отдельном процессе PolyStrata на своём порту рядом с
основной Strata, где для агентов devlab стоит Qwen. Обе модели работают одновременно, и запрос
дворецкого больше не ждёт конца агентского запроса и не гоняет модели туда-сюда. Компаньон — имя
модели, запросы к которому идут в его собственный upstream; `StrataSwitch` при этом ничего не
переключает.

Компаньон занимает видеопамять, поэтому он живёт только пока им пользуются: пока он запущен,
основная модель держит резерв `main_reserve_active_mib`; когда компаньон молчит `idle_stop_s`, его
процесс останавливается, и основная модель получает резерв обратно
(`main_reserve_idle_mib`, по умолчанию 0 — вся видеопамять).

### Порядок перестройки видеопамяти

Видеопамять у обеих служб (Strata и PolyStrata) меняется на лету запросом
`POST <upstream>/v1/vram` с телом `{"reserve_mib": N}` — сколько МиБ оставить свободными для
других; ответ 200 при успехе. Если у сервера в этот момент идёт запрос, он ждёт его конца и иногда
отвечает 409 — тогда запрос повторяется каждые `poll_s`, пока не упрётся в `max_wait_s`
(`VramFailed`). Перестройка занимает доли секунды.

Порядок жёсткий, иначе не хватит видеопамяти:

- первый запрос компаньона: сначала `POST /v1/vram` основной модели с `main_reserve_active_mib`,
  и только потом `launcher` компаньона. Запрос резерва уходит всегда, даже если маршрутизатор не
  знает, какая модель загружена (`switch.current is None` сразу после его перезапуска, хотя Qwen
  уже работает). Пропускается он, только если основная Strata не принимает соединение
  (`MainUnreachable`): ужимать нечего. Находка 2026-11-15: проверка по `switch.current` после
  рестарта маршрутизатора запускала Gemma рядом с Qwen на всей видеопамяти;
- остановка по простою: сначала `stopper`, потом `POST /v1/vram` основной модели с
  `main_reserve_idle_mib`.

### Остановка по простою

`Companion` ведёт счётчик активных запросов и время последнего запроса. Фоновая задача раз в
`poll_s` зовёт `stop_if_idle()`: процесс останавливается, только если компаньон запущен, активных
запросов нет и с последнего запроса прошло `idle_stop_s` (по умолчанию 1800 с). Задача стартует в
`on_startup` приложения и отменяется в `on_cleanup`. Сбой остановки (не 0 у `stopper`, 409 до
`max_wait_s`, недоступный сервер) не роняет задачу: она пишет `log.warning` и пробует снова на
следующем витке.

`launcher` и `stopper` — обычные argv, они запускаются тем же `run`, что и скрипты `launchers`
(см. `LaunchFailed`): `launcher` возвращает 0, когда процесс готов отвечать; `stopper` — когда
процесс остановлен. Код не 0 — `LaunchFailed`, клиенту 502, компаньон остаётся помеченным
остановленным (для `stopper` — помеченным работающим, чтобы следующая попытка повторилась).

### Маршрут запроса

В обработчике `POST /v1/chat/completions` имя компаньона — приоритетный путь: `enter_priority()`
обрывает обычные запросы к основной модели (обычные повторяются сами, клиент обычного видит только
более долгий ответ), затем `ensure_running()`, затем пересылка в `companion.upstream` теми же
`relay_chat`/`relay_stream` — потоковый ответ компаньона идёт как обычный поток. В `finally` —
конец запроса и `leave_priority()`. `acquire` основной модели для компаньона не вызывается.
`Authorization` пересылается и компаньону, ключ не хранится и не логируется; он же используется в
запросах `/v1/vram`. `GET /v1/models` отдаёт и имя компаньона.

Имя компаньона не должно совпадать с именами `launchers` или `aliases`, иначе `UnknownModel` при
загрузке конфига: иначе запрос к имени ушёл бы не туда.

### TOML

```toml
default = "qwen3.8"

[companion]
name = "gemma4-alfred"
upstream = "http://127.0.0.1:8086"
launcher = ["/models/sa-home/poly/gemma-on.sh"]
stopper = ["/models/sa-home/poly/gemma-off.sh"]
idle_stop_s = 1800.0
main_reserve_active_mib = 3072
main_reserve_idle_mib = 0

[launchers]
"qwen3.8" = ["/models/sa-home/stand/qwen-on.sh"]
```

Секция `[companion]` необязательна: без неё поведение маршрутизатора прежнее — компаньона нет,
`/v1/vram` не вызывается, фоновой задачи нет. Обязательные поля — `name`, `upstream`, `launcher`,
`stopper`; `idle_stop_s` по умолчанию 1800 с, оба резерва по умолчанию 0.

## Запуск

```
python -m sa_home_bot.llm.strata_switch --config /etc/strata/switch.toml
```

Аргументы: `--config` (путь к TOML), `--host` (`127.0.0.1`), `--port` (`8090`),
`--upstream` (`http://127.0.0.1:8080`). При старте приложения маршрутизатор загружает `default`
(он же прогревает модель), дальше переключается по запросам.

## Коды ответов

| Код | Когда |
| --- | ----- |
| 400 | нет поля `model`, тело не JSON-объект, имя модели нет ни в `launchers`, ни в `aliases` |
| 502 | скрипт запуска вернул не 0 (`LaunchFailed`), `launcher`/`stopper` компаньона вернул не 0 или Strata (для компаньона — PolyStrata) не ответила |
| 503 | модель занята и переключение невозможно (`SwitchBusy`), текст `модель занята, переключение невозможно`; основная модель не отдаёт видеопамять компаньону до `max_wait_s` (`VramFailed`), текст `основная модель занята, видеопамять не перестроена` |
