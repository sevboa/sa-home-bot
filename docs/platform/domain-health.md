# Домен здоровья (domain/)

Чистые модули без БД, сети и aiogram; тестируются изолированно. Уведомление — функция от перехода состояния (`Transition`), а не от мгновенного значения.

## Гистерезис

`domain/hysteresis.reconcile_band` — общее ядро для температур (`health.py`) и host-метрик VPS (`host.py`). Политика порогов вызывающей стороны выдаёт полосу `BAND_OVER` / `BAND_MID` / `BAND_UNDER`; здесь только счётчик подряд идущих срезов. Из OK счётчик копит подряд OVER-срезы, по достижении `consecutive_to_alert` — ALERTING. Из ALERTING копит подряд UNDER, по `consecutive_to_clear` — возврат в OK. MID (мёртвая зона) и противоположная полоса сбрасывают счётчик. `vpn_check.py` — тот же принцип, но булев (N неудач подряд — alerting, M успехов подряд — ok).

## Политики порогов (policy.py)

- `FixedThresholdPolicy`: зона `temp >= warn` тянет в alerting, `temp <= warn - delta` — в ok, между ними мёртвая зона сбрасывает счётчик.
- `BaselinePolicy`: порог `min(warn_c, mean + k_sigma * max(std, min_std_c))` по последним `baseline_window` показаниям (популяционное стандартное отклонение). Baseline может только опустить порог ниже `warn_c` (раньше поймать перегрев на обычно холодной машине), но не поднять: `warn_c` — жёсткая страховка. Пока показаний меньше `min_samples`, работает как фиксированная (холодный старт). Гистерезис тот же.

## Host-метрики VPS (host.py)

У виртуалки нет температур, зато есть индикаторы деградации: переподписка провайдера (CPU steal), контеншн хранилища (iowait), давление памяти, заполнение маленького диска. Модель показания отдельная от температурной (значение — %, load или счётчик), гистерезисный автомат общий. `METRICS` — реестр метрик с дефолтными порогами; перекрываются в `[sensors.host.thresholds.<метрика>]` конфига ноды (`with_thresholds`). Направления: `DIR_ABOVE` (тревога при росте: steal, iowait, load, диск) и `DIR_BELOW` (тревога при падении: свободная память). У метрики есть мёртвая зона возврата (в единицах метрики) и дополнительная фраза-подсказка в тексте оповещения. События host-метрики строит `jobs/scan.py`.

## SMART (smart.py)

Отслеживаются счётчики деградации, которые в исправном диске не растут (`MONITORED_SMART_ATTRS`: переназначенные, кандидаты на переназначение, нечитаемые при offline-скане, ошибки интерфейса CRC). Значение берётся как ведущее число `raw.string`: `raw.value` у части дисков пакует доп. поля (Hitachi отдаёт 589855 вместо 31). Атрибут 187 (Reported_Uncorrect) сознательно не отслеживается: raw ненадёжен (заглушка 65535 / упакованное значение у разных вендоров) и давал бы ложные тревоги; реальная деградация всплывает через 197/198 и `smart_status`. `diff_smart`: первое наблюдение (`prev is None`) события не даёт, только baseline; рост счётчика или ухудшение класса здоровья (ok < warning < failed) — degraded (доминирует); снижение/улучшение — recovered; `None → ok` не изменение.

## Модели (models.py)

- `DiskSummary` собирается фоном раз в `scan_cron` (`SensorScanJob`) и кэшируется в БД (`DISK_SUMMARIES_KEY`): живой smartctl/LHM-опрос на каждый `/status` делал его медленным (особенно с тормозящим USB-диском или на Windows). `health`/`temperature_c` = None, если SMART недоступен (у eMMC физически); `kind` по умолчанию `hdd` — совместимость со старыми мониторами.
- `PowerEvent`: каждая завершённая boot-сессия — одно событие: штатное (`POWER_CLEAN`, `down_at` — точный момент) либо внезапный обрыв (`POWER_UNEXPECTED`: в wtmp только `crash`, `down_at` оценивается по последнему событию systemd-журнала, `down_approx=True`).
- `SmartSnapshot` — нечастый `SmartScanJob` (`smartctl -H -A`, без self-test); `health` — агрегат `smart_status` + сбойные сектора.

## Рендер (render.py)

- Настроения температуры (🥶/🙂/🥵/🔥) используют те же `warn_c`/`crit_c`, что реальные алерты: эмодзи не должен противоречить наличию уведомления. «Холодно» — порог ниже алертов, даташитами не регламентируется (нижний предел 0°C бессмыслен): для дисков комнатная температура (рабочий диапазон Seagate Momentus 5400.6 и Hitachi Travelstar Z5K320 — 0–60°C), для CPU измеренный холостой ход 33–37°C (Tjunction max Celeron N3350 ≈105°C), для GPU холостой ход Tesla V100 SXM2 на mycraft 33–41°C.
- eMMC: SMART физически нет — иконку здоровья не показываем; у SMART-способных дисков ❔ значит «данных SMART нет» (нет прав/программы/холодный старт), причину объясняет ⚠️-строка requirements. Занятое место показывается как «7 из 57 ГБ (10%)».
- GPU — строка на карту, не максимум: каждая карта отдельное устройство со своей идентичностью (V100 SXM2 и RTX 3060 вели себя совершенно по-разному).
- Отключения: `last` даёт время с локальным offset, journal в UTC — приводятся к локальной зоне процесса. `/downtime` — страницами по 10. В карточке VPS заголовок ⚠️ вместо 📊, если хоть одна метрика в alerting; PSI/OOM показываются только когда сами в alerting. В английском «<» экранируется как `&lt;` ради HTML parse_mode.

## vpn_check (domain/vpn_check.py)

Ключ состояния расширен этапом 39.0.7 (разбор 2026-09-18): `node` — наблюдатель, `server` — кого проверяли, `transport` — awg/reality. Один `(server, transport)` проверяется несколькими наблюдателями независимо; `rollup_status` сводит их для индикатора в `/vpn`: все OK — OK; все согласны в обратную сторону — ALERTING; иначе PARTIAL («доступно частично», оранжевый — решение владельца 2026-09-18). Вызывающий сам фильтрует записи до нужной пары.
