# Служба torrents (адаптер qBittorrent)

Минимальная служба: proto-сервер поверх `TorrentsService`, без БД и планировщика. Состояние читается из qBittorrent на каждый запрос.

## Действия

- `add` — раздача по magnet/URL или по содержимому .torrent. Файл едёт по протоколу base64-строкой (`ActionParam` — только string|int|float|bool), метафайлы на порядки меньше лимита сообщения (`MAX_MESSAGE_BYTES` = 1 МиБ). Директория сохранения — конечный список `save_dirs` из конфига, не свободный ввод: бот строит кнопки по `choices` действия и ходит только к этой службе.
- `list` — read-only срез закачек (имя, прогресс, состояние, скорость, оценка). Появился 2026-07-27 вместе с тулом swarm_status. Путей на диске и хэшей в ответе нет: хэш ничего не даёт модели, только раздувает контекст. `with_hash` ставит только бот-панель (`bot/torrents_view`) напрямую через `args`, не через объявленный `ActionParam`, поэтому модель его вызвать не может.
- `pause`/`resume` — адресуются по имени, не по хэшу. Разрешение делает `_select`: явное «все» → точное имя → хэш → узнаваемая часть имени. Порядок важен: точное имя, оказавшееся подстрокой другого («Foo» при живом «Foo.S02»), иначе считалось бы неоднозначным. Неоднозначность — честная ошибка со списком кандидатов. «Останови всё» — отдельное явное слово, а не побочный эффект пустой подстроки.
- `search` — поиск встроенным движком qBittorrent и его плагинами (`search_start`/`search_results`). Заведён 2026-07-29: выдача SearXNG даёт заголовок и ссылку, а magnet лежит внутри темы трекера, часто под логином. Плагин логинится сам и отдаёт имя, размер, сиды.
- `search_smart` — заведён 2026-08-09, переписан под явные `phrase` + `words` 2026-08-10. `phrase` уходит трекеру как непрерывная подстрока (в сырой пул `SEARCH_SMART_FETCH_LIMIT` с одного задания), `words` — AND-фильтр в Python поверх сырой выдачи (casefold-подстроки, любой порядок). Модель сама решает, что в `phrase` (устойчивая часть названия), что в `words` (год, качество, сезон). Автоматической разборки свободного текста нет. Модели отдаётся не больше `SEARCH_LIMIT`.
- `details` — карточка раздачи: страница трекера без разметки. Только сайты с установленным плагином, одна страница за вызов.
- `space` — свободное место директорий считается локально (`shutil.disk_usage`), qBittorrent нужен только ради `downloading_left_bytes` (сколько ещё докачать принятым); если он молчит, поле `null`, а место всё равно отдаётся.
- Лимит скорости: общий для download и upload одним значением (потолок из бот-панели — домашний канал слабый); 0 — соглашение qBittorrent «без ограничения».

## Скачивание метафайла (nova2dl)

Ссылка из результатов поиска — не magnet, а `dl.php?t=…`, отдаётся только авторизованному. Поэтому `add` для таких ссылок качает метафайл через `nova2dl.py` самого qBittorrent (`_fetch_via_plugin`), как его GUI: плагин отдаёт .torrent своей сессией, мы добавляем файл уже с нужным `save_path`. Штатное `search/downloadTorrent` Web API кладёт раздачу в директорию по умолчанию, мимо выбора. Успех — одна строка «<путь> <ссылка>», всё прочее (в т.ч. текст ошибки плагина) — неудача. http(s)-ссылка принимается только как находка своего же поиска (`_plugin_for`): с трекера под логином вернулась бы страница входа, а качать по произвольному адресу из разговора незачем. Поддомен считается тем же сайтом (находка 2026-07-29: rutor ищет на `rutor.info`, отдаёт с `d.rutor.info`). Путь к движку и плагинам: пусто в конфиге — путь по умолчанию Linux-сборки.

## Лестница запросов

Находка 2026-07-29: rutor ищет запрос как непрерывную фразу, любое лишнее слово обнуляет выдачу («задача трёх тел» — 10 находок, «… 2024» — ноль). Модель упорно дописывает год, качество, имя релизера. Поэтому `_query_ladder`: запрос как есть → без шумовых слов (год, S01/S01E02, 1080p/720i/2160p) → всё короче. Потолок 5 попыток (каждая — живой запрос ~1–2 с). Пусто из-за лишних слов — пробуем короче; сломанный плагин короче не починится.

Сбой плагина приезжает не ошибкой, а фальшивой «находкой»: имя «[запрос][Error]: …», ссылка «<сайт>/error», 100 сидов, терабайт. Такие находки отфильтровываются — иначе модель честно предложит скачать «рекордную раздачу». Сортировка по сидам. Общее число находок (`total`) отдаётся, чтобы показать «N из total»; в ответ добавляется предупреждение, что выдача шире запрошенного и год/качество надо проверять по именам.

`SEARCH_LIMIT` был 10, уменьшен до 6 2026-07-29 (вместе с декларациями тулов выдача выбивала окно num_ctx=8192, ответ приходил пустым), с 2026-07-25 num_ctx поднят до 24576 — вернули 10.

## Страницы трекера (details)

Живая находка 2026-07-29: на rutor техническая карточка лежит после синопсиса (~3300 из 16000 знаков), поэтому берётся голова страницы и отдельным куском техническая часть (`DETAILS_HEAD_CHARS`). Кодировка из заголовков: rutor — utf-8, rutracker и родня — cp1251. Вырезание блоков по id/class ловит не всё (меню — вложенные div, нежадный «до `</div>`» останавливается раньше); верхнее меню узнаётся по форме: короткие строки-ссылки до первой содержательной. Промахнуться безопасно: не вырезали — больше мусора, вырезали лишнее — текст короче. User-Agent обычного браузера: с «Python-urllib» часть трекеров отказывает. Со страницы magnet берётся напрямую.

## Прочее

- Раздача не принимается вовсе при свободном месте ниже `MIN_FREE_BYTES` (общий порог для всех директорий; размер по magnet заранее неизвестен, поэтому проверить «влезет ли именно это» нельзя, но добивать диск досуха — можно и нужно не дать).
- `QBIT_ETA_INFINITY_SECONDS` = 8640000 (100 суток) — qBittorrent отдаёт его как «неизвестно/бесконечность»; наружу уходит `None`.
- Состояния qBittorrent переводятся в понятные (две семьи префиксов: в qBittorrent 5 `paused*` переименованы в `stopped*`); `torrents_pause/_resume` — версионно-безопасные псевдонимы библиотеки.
- Задание поиска удаляется сразу после чтения результатов, «страниц» нет.
- Список ограничен числом раздач, сортировка по убыванию активности (sort/limit делает сам qBittorrent).
- Сигнальные обработчики регистрируются до `start()` сервера: он ждёт появления своего адреса, и остановка иначе не обрабатывалась бы.
