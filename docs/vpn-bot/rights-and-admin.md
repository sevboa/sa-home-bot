# Права и админские экраны

## Две оси (решение 2026-09-24)

В /guests группа "VPN" выдаётся и снимается целиком ("пускаем ли вообще"). Тонкая настройка - в разделе "Все гости" /vpn:
- ГДЕ и СКОЛЬКО - допуск к локации и постоянная база в ГБ. Правом не выражается (локации живут в рое, у каждой свой счёт за трафик); хранится в службе (`vpn_chat_access` каждой ноды). Пресеты 50/100/200/500/1000 ГБ и шаг +-50: свободный ввод требует FSM, которого в боте нет.
- ЧТО ИМЕННО - тумблеры `VPN_TOGGLES` (видеть карточку, свои устройства, трафик, прокси Telegram) - обычные права `действие@vpn` в гостевой подписке, правит `Gatekeeper.set_guest_rights`. Тумблер - рабочий комплект: "выпустить" без "перевыпустить"/"отозвать" - сломанное умение. Неполный набор дожимается до полного, а не снимается; снять - нажать ещё раз. Состояние читается из подписки в момент нажатия, поэтому две вкладки экрана не расходятся. Тумблер "Видеть карточку" - входной билет: без `usage@vpn` команда /vpn недоступна (`bot/commands.py::VPN`).

Состояние прав считается через `allows_action`, а не вхождением строки в `allowed_commands`: владельцу с `*` или `*@vpn` экран должен показывать включённое.

Права экранов: смотреть - `peers@vpn`, менять допуск и квоту - `set_access@vpn`, менять умения гостя - `set_rights@vpn` (действие без службы: книга подписок живёт в боте). Гость в списке сортируется: сначала те, у кого группа VPN выдана.

Сообщение гостю об изменении допуска бот шлёт сам (события службы ходят по другому поводу); есть ли у гостя устройства, спрашивает у нод, не вышло - без обещаний. Старая нода без `set_access` отвечает `ERR_UNKNOWN_ACTION` - это рассинхрон версий, а не отказ.

Кнопка "Все гости" рисуется по тому же признаку, по которому проверяется право (`peers@vpn`): раньше рисовалась по одному праву, а слала другое и отказывала админу с точечным правом.
Кнопка "Проверка сети" есть у любого живого vpn-инстанса (39.0.7(f)): состояние проверок реплицировано на все живые, пробник умеет и reality.
Прокси Telegram - право `proxy_link@vpn`, не админство (решение 2026-09-24); кнопка без node_id фанаутит `proxy_link` по всем живым серверам (решение 2026-09-20). Гостю с открытым только прокси показывается мини-карточка вместо отказа. SOCKS5-адрес - только админу: он служебный для ботов внутри tailnet. "Сменить секрет" рвёт ссылку у всех, поэтому без права кнопки нет вовсе.

## Заявки владельцу (57.3a, 57.6b)

"Позвать на помощь" мастера и "Сообщить о проблеме" - один механизм (`vpn_help.send_help_request`): владельцу "VPN: проблема у ..." с кнопками "Ответить" и "Карточка гостя". Адресаты - `notify_admins` (чаты с полным доступом). Троттлинг в памяти, раз в 600 с на человека, общий для обеих кнопок. `report@vpn` отдельным тумблером не выдаётся: он есть у всех с `usage@vpn`; `reply@vpn` - только у админов. Ожидания reply - в памяти процесса `(chat_id, message_id)`, TTL 30 минут. Пробник `chat_id=0` - не человек: заявок от него нет, он не попадает в уведомления.

## Инструмент `vpn` Альфреда (57.8)

`vpn_agent` - тот же вход, что кнопки: статус из `vpn_devices`, мастер и настройки присылаются теми же экранами, секреты через инструмент не проходят вообще. Ответы справки (`vpn_facts`) - один источник для кнопок и описания инструмента. `vpn_agent` импортируется из `bot/tools.py` лениво (тянет aiogram).
