# Устройства и ноды

## Где живёт служба `vpn` (этап 39, 39.0.2)

Бот не шлёт команды на хардкод-адрес сервера: ноды с запущенной службой `vpn` находятся по их состоянию (`state["services"]`), тем же приёмом, что карточка ноды в `/nodes` (`bot/node_view.py`). `vpn_nodes.resolve_vpn_dst` выбирает ОДНУ ноду (держателя конкретного подключения, `vpn_peers.server`, либо первую живую); `fanout` (39.0.5) собирает ответы со ВСЕХ живых серверов - карточка показывает подключения и квоту каждой локации отдельно. Нода, отвалившаяся между опросом и вызовом, просто выпадает из ответа: карточка с одним живым сервером полезнее отказа. Модуль `vpn_nodes` намеренно без aiogram: его тянет `bot/tools.py`, а тот - служба tasks (тот же запрет, что в `wake_core`).

`probe_targets` раскладывает живые серверы в плоский отсортированный список пар (сервер, транспорт) для пробника (39.0.7(d)); индекс пары участвует в именовании netns/veth/подсетей в `node/fixups.py`, поэтому порядок детерминирован. Свой сервер из проверок исключён по решению владельца 2026-09-18.

## Модель устройства (57.2)

Устройство - это `device_label`, общий для всех нод и транспортов; под ним до четырёх подключений {нода x транспорт}. Отдельной таблицы нет: каждая нода отдаёт в `usage` с `chat_id` свою часть (`device_usage`), `vpn_devices.build_devices` склеивает их по имени. Модуль чистый (без aiogram и сети), поэтому годится и боту, и инструменту `vpn`. Пробник `chat_id=0` сюда не попадает (`vpn_callbacks.PROBE_CHAT_ID`, `is_probe`): запросы идут по chat_id человека. Ноды старее 57.1 не отдают `device_usage` - устройства собираются из `devices`, трафик считается нулём; ноды без поля `broken` не называются сломанными.

Страна = сервер (нода); `Country.label` - "🇳🇱 Нидерланды" из `[vpn].location`, `short` - флаг (или название без флага), для узких кнопок.
