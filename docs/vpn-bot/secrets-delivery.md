# Доставка секретов гостю

Приватный ключ нигде не хранится: ни в БД (служба хранит только публичный), ни в callback_data (лимит 64 байта). Он живёт в памяти процесса (`vpn_secrets.PendingVpnSecrets`) до выдачи или до `[vpn].config_message_ttl_s`, после чего бот сам удаляет сообщения. После рестарта токены не находятся - гость видит "Ссылка устарела". Токен в callback - `secrets.token_urlsafe(6)`.

## Порядок способов (решение владельца 2026-08-04)

Критерий - `prior_device_count` из ответа службы:
- первое устройство чата настраивается почти наверняка прямо с этого телефона: сразу файл `.conf` (тап на файл, "Открыть с помощью", AmneziaWG импортирует без копирования - живая находка 2026-08-03), QR по кнопке;
- второе и далее - скорее для другого устройства или человека: сразу QR, файл по кнопке.

Кнопка одна и исчезает после использования (остальные кнопки-секреты того же сообщения, например QR по странам, остаются). Право кнопки "забрать выданное" - то же, что у действия, выдавшего секрет (`issue@vpn`/`reissue@vpn`), отдельного не заводили (тот же приём, что у `apk`/`apk:send`).

## Reality

Подключением является deep-link и `vless://`-ссылка в тексте сообщения (tap-to-copy); файл и QR из подписи содержат только РФ-маршруты и DNS и нужны один раз при первой установке приложения. Эти пояснения - в подписях, менять их нельзя.

## Удаление по TTL

Одна реализация (`vpn_delivery.cleanup_later`): ждать TTL, сбросить токены, удалить сообщения. Отправленный по кнопке секрет тоже исчезает по TTL.

## APK (`vpn_apk.deliver_apk`)

Метаданные (версия, размер, sha256, `telegram_file_id`) идут обычной командой; байты - только если file_id нет (новая версия) или Telegram его отверг (протух, например при смене токена бота): чанками `CHUNK_BYTES` с запасом от MAX_MESSAGE_BYTES протокола роя. `message_thread_id` обязателен: без него документ уезжает в общий топик (живой баг 2026-08-03).
