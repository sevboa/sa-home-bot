# callback_data и экраны /vpn

Все кнопки строятся `commands.action_callback` по схеме `act:vpn:<действие>[:<значение>[:<нода>]]`. Право на действие проверяет `CallbackAuthorizationMiddleware` (`действие@vpn`), обработчик только исполняет и рисует. Диспетчеризация в `handlers.vpn.handle_action` идёт из `bot/handlers/node.py::on_dynamic_action` (один обработчик "act:"-кнопок на все службы, разбор по service). Лимит Telegram на callback_data - 64 байта, поэтому устройство в кнопке задаётся 8-символьным хэшем имени (`vpn_devices.device_key`), по свежему usage он разрешается обратно в имя.

Callback-строки уже разосланных сообщений должны продолжать работать: `vpn_card`, `apk`, `grant_extra`, `usage_all`, префиксы значений `~`, `f_`, `t_` менять нельзя.

## Действие `vpn_card` (право `vpn_card@vpn`)

Локальные экраны без запроса к службе. Первый символ значения - экран:

| Значение | Экран |
|---|---|
| пусто | главная |
| `m` | список устройств |
| `d<ключ>` | карточка устройства |
| `x<ключ>` | подтверждение удаления |
| `r<ключ>[-<подпись>-<маска>]` | галочки перевыпуска (57.5): маска - hex, бит i = i-й выданный транспорт в стабильном порядке (страны как у серверов, VLESS перед AmneziaWG); подпись (4 hex) - хэш списка, изменился между нажатиями - выбор сбрасывается |
| `R<ключ>-<хэш ноды>-<коды транспортов>` | экран перевыпуска с предвыбором после "сервер переустановлен" (57.7) |
| `l<ключ>` | "Получить настройки" (57.11): одно пересылаемое сообщение со ссылкой на страницу, URL-кнопка, без callback-кнопок, по TTL не удаляется (утечка ссылки лечится перевыпуском - токен меняется) |
| `g<ключ>` | "Другие способы" без страницы (VLESS - Hiddify / AmneziaWG) |
| `a<ключ>` | AmneziaWG: выбор страны |
| `n` | новое устройство: выбор платформы |
| `w...` | мастер (ниже) |

## Мастер 57.3a (`vpn_card:w<экран>...`)

`p` выбор устройства, `x` "Я разберусь сам" (экспертная главная), `b/c/d` шаги (файл настроек / страница настроек / проверка), `a` - старый код установки, ведёт на страницу (57.11), `d` ("✅ Готово" под сообщением со ссылкой) с 2026-10-19 не спрашивает, а проверяет: `device_online` по всем нодам; на связи - "Подключено через <способ>, сервер <страна>" (свежайшее соединение) и "На главную"; нет - "🔁 Повторить попытку" (обратно к ссылке, `c`), "🙋 Позвать на помощь" (шаг `d`), "На главную"; ни одна нода не ответила - прежний вопрос "Заработало?". `y` "Заработало", `f/o/h` + `<шаг><платформа><ключ>` - "Не получается" / другая страна / позвать на помощь. Шаг `n` - устройство не удалось создать. Платформа - одна буква (`i/a/c`). Создаёт устройство отдельная кнопка `issue:~w<платформа>` под обычным `issue@vpn`. С 57.13 `needs_settings_file` всегда False: настройки - сразу страница, файл в Telegram остался только под "Другие способы".

## Экспертные значения (префикс `~`)

- `issue:~v<ключ>` VLESS - Hiddify (довыпускает недостающие страны), `~s<ключ>` файл настроек ещё раз, `~g<ключ>:<нода>` AmneziaWG в стране, `~n<платформа>` новое устройство в экспертном режиме (после создания - страница в том же сообщении, 57.13), `~w<платформа>` создание в мастере.
- `reissue:~m<ключ>-<подпись>-<маска>` перевыпустить выбранные; `~r<ключ>`/`~a<ключ>` + нода - VLESS/AmneziaWG этой страны; `~f<ключ>` + нода - "Починить" (только сломанные подключения); `~g<ключ>:<нода>` - "Выпустить новый" после предупреждения "новый заменит старый".
- `revoke:~d<ключ>` - удалить устройство целиком, на всех нодах и транспортах.
- `issue:t_<транспорт>` - выбор технологии из пикера (если нода несёт оба транспорта); `issue:f_<токен>` - забрать отложенный секрет.
- Старая карточка (группы и ноды без VLESS) использует прежнее значение "имя устройства" без префикса `~`.

## Другие действия

- `apk`: пусто - список справки, `q<код>` - ответ, `nostore` - "магазин недоступен", `send` - выслать APK (второе нажатие; на iOS сайдлоада нет, апстор надёжнее .apk - решение 2026-08-04, кнопка после отправки прячется).
- `report` / `reply` (57.6b): `report:m[<ключ>]` причины, `report:f` то же из справки, `report:c|s|w[<ключ>]` причина кнопкой, `report:o[<ключ>]` "Другое" через ForceReply, `reply:<chat_id>` - владельцу "Ответить".
- `resolve_request` значение `<id>_approve|<id>_deny` (кнопки под уведомлением о заявке на трафик).
- `peers` (экраны гостей), `set_access`, `set_rights` - см. [rights-and-admin.md](rights-and-admin.md).
- `proxy_link`: пусто - экран, `qr` + нода - QR страны, `d` - секрет и порт (только при `proxy_rotate_secret@vpn`).

## Главная /vpn

Есть устройства - новая главная (57.3): остаток квоты и предупреждение словами. Нет устройств - первый экран мастера (личка и без "Я разберусь сам"); после "Я разберусь сам" - та же новая главная с пустым списком (57.4). Группа или нет VLESS-сервера - прежняя карточка (`vpn_legacy_card`): расход по локациям, устройства, кнопки по правам. Клавиатуры строго по правам чата: раньше кнопки рисовались безусловно и отказывали при нажатии.

Выдача ключа начинается так: у ноды несколько живых локаций - пикер локации (этап 39.0.5, только открытые гостю: транспорты из `get_state`, допуск из `usage` с chat_id), одна - она адресуется явно (иначе "первая живая" могла быть закрытой), пусто - бот не лезет, отказ даёт служба. Потом, если нода несёт оба транспорта, пикер технологии. Порядок транспортов в списках: AmneziaVPN первым (57.13), незнакомые транспорты (нода новее бота) в хвост.

Допуск `allowed`: отсутствие поля значит "нода не ведёт допуск" (ещё не обновлена); дефолт True намеренный - инвертированный запер бы UI живым гостям на время раската.
