# Индикаторы и уведомления

## Индикаторы проверок (39.0.7(f))

Трёхцветные по решению владельца 2026-09-18: зелёный - сервер видят все наблюдатели, оранжевый - часть (кому-то уже заблокирован), красный - никто. Виден всем гостям, не только админу: "почему не подключается" - первый вопрос гостя. Нет данных (нода старая, пробники не отчитались, отчёты протухли - `CHECK_STALE_FACTOR` службы) - индикатора нет вовсе: молчание честнее выдуманного зелёного. Для кнопки пикера локации - один сводный цвет тем же доменным правилом `vpn_check.rollup_status`. Легенда показывается, только если есть не зелёные.

Админский экран проверок: цвет пары (сервер, транспорт), под ним по строке на наблюдателя со всеми целями (разбивка по наблюдателю отличает блокировку в одной стране от смерти сервера). Имя цели выводится из URL, а не из словаря: список целей растёт правкой конфига. "Запустить проверку" редактирует тот же экран на месте с пометкой "в процессе" (решение 2026-08-17).

Главная: если у одной страны нет данных проверки - одна строка без названия; подсказка про другую страну - когда одна не работает, а другая работает. Проверка VLESS главнее остальных (основной способ подключения).

## Уведомления о событиях службы (57.7)

Единый вид: страна (флаг, в длинных фразах и название) в каждом сообщении. Страна - по ноде-источнику события (`node`, `location`); у ноды старее 57.7 `location` нет - берётся запомненная подпись (`vpn_nodes.known_server_label`, файл `vpn_known_servers.json`), нет и её - без страны. Тексты на "вы", без пола. При переустановке сервера гость получает список задетых устройств по транспортам и кнопку "Обновить" (одно устройство - экран перевыпуска с предвыбором, несколько - список); владельцу - число подключений и людей. Пробник `chat_id=0` в уведомления не попадает.

Память о серверах (`vpn_nodes.remember_servers`) нужна, чтобы админу показать "сервер недоступен", а не молча потерять локацию лежащей ноды.
