# Индикаторы и уведомления

## Индикаторы проверок (39.0.7(f))

Трёхцветные по решению владельца 2026-09-18: зелёный - сервер видят все наблюдатели, оранжевый - часть (кому-то уже заблокирован), красный - никто. Виден всем гостям, не только админу: "почему не подключается" - первый вопрос гостя. Нет данных (нода старая, пробники не отчитались, отчёты протухли - `CHECK_STALE_FACTOR` службы) - индикатора нет вовсе: молчание честнее выдуманного зелёного. Для кнопки пикера локации - один сводный цвет тем же доменным правилом `vpn_check.rollup_status`. Легенда показывается, только если есть не зелёные.

Админский экран проверок: цвет пары (сервер, транспорт), под ним по строке на наблюдателя со всеми целями (разбивка по наблюдателю отличает блокировку в одной стране от смерти сервера). Имя цели выводится из URL, а не из словаря: список целей растёт правкой конфига. "Запустить проверку" редактирует тот же экран на месте с пометкой "в процессе" (решение 2026-08-17).

Главная: если у одной страны нет данных проверки - одна строка без названия; подсказка про другую страну - когда одна не работает, а другая работает. Проверка VLESS главнее остальных (основной способ подключения).

## Уведомления о событиях службы (57.7)

Единый вид: страна (флаг, в длинных фразах и название) в каждом сообщении. Страна - по ноде-источнику события (`node`, `location`); у ноды старее 57.7 `location` нет - берётся запомненная подпись (`vpn_nodes.known_server_label`, файл `vpn_known_servers.json`), нет и её - без страны. Тексты на "вы", без пола. При переустановке сервера гость получает список задетых устройств по транспортам и кнопку "Обновить" (одно устройство - экран перевыпуска с предвыбором, несколько - список); владельцу - число подключений и людей. Пробник `chat_id=0` в уведомления не попадает.

Память о серверах (`vpn_nodes.remember_servers`) нужна, чтобы админу показать "сервер недоступен", а не молча потерять локацию лежащей ноды.

## Связки и охваты (65.3, 2026-11-12)

События службы `vpn` — `vpn_link_changed` и `vpn_outage`. Оповещение короткое: одна-две строки, без картинки и без клавиатуры. Рендер — чистые функции `bot/vpn_link_notify.py`, без aiogram.

Значки: охваты 🌍 (`global`) и 🇷🇺 (`russia`), уровни 🟢 (`ok`), 🟡 (`partial`), 🔴 (`down`), неизвестный уровень — ⚪. Флаг сервера — первое слово подписи локации (`vpn_nodes.known_server_label`): `🇳🇱 Нидерланды` даёт `🇳🇱`; у сервера без подписи вместо флага имя сервера. Вторая строка — строка охватов: по охватам `SCOPES` по порядку, только у которых непустой словарь серверов; серверы как `<флаг><значок уровня>`, части охватов соединяются ` · `. Пример: `🌍 🇳🇱🟢 🇺🇸🟢 · 🇷🇺 🇳🇱🔴 🇺🇸🟡`.

Тексты первой строки:

- `vpn_link_changed`, `to == "down"`: `🔴 <сервер> · <транспорт> — не работает <значок охвата> (<code>node</code>)`
- `vpn_link_changed`, `to == "ok"`: `🟢 <сервер> · <транспорт> — снова работает <значок охвата> (<code>node</code>)`
- `vpn_outage`, `to == "down"`: `🚨 <сервер> — VPN недоступен <значок охвата>`
- `vpn_outage`, `from == "down"` и `to == "ok"`: `✅ <сервер> — VPN снова доступен <значок охвата>`
- `vpn_outage`, `from == "down"` и `to == "partial"`: `✅ <сервер> — VPN снова доступен <значок охвата> (частично)`

Если `scope` нет или он неизвестен, значок охвата и пробел перед скобкой опускаются. Имя транспорта — `vpn_devices.TECHNICAL_TRANSPORT_NAME`, неизвестное имя пишется как есть; сервер и нода — через `html.escape`.

Рассылка — только подпискам, принимающим этот тип события (`book.accepting(имя события)`), а не всем админам. Антидубль по ключу без поля `scopes`: для `vpn_link_changed` — `name|node|server|transport|to`, для `vpn_outage` — `name|scope|server|to`. Событие приходит от каждой ноды `vpn` с одинаковым `scopes`, потому что `scopes` считается по всем связкам сразу; без `scopes` в ключе каждое событие прошло бы по разу с каждой ноды. Окно антидубля то же, что у проверок (`VPN_EVENT_DEDUP_S`), чистка словаря вынесена в `node_events._seen_recently` — ею пользуются обе ветки.

## Картинка суточного отчёта (65.6, 2026-11-12)

Одна картинка на пару (сервер, охват): график задержек за сутки, линии — транспорты. Масштаб по вертикали общий на всех картинках — 0–2 с, поэтому листанием сравниваются абсолютные значения, а не «относительная кривизна» конкретной панели. Палитра транспортов тоже одна на всех (`awg`, `awg_alt`, `reality`, `reality_alt`; неизвестный транспорт получает цвет из `FALLBACK_COLORS` по порядку появления), легенда внизу панели.

Верхняя полоса — «нет связи»: значение `>= MAX_MS` (2 с и больше) рисуется не по своей высоте, а строкой в верхней полосе, по строке на транспорт, чтобы несколько «мёртвых» транспортов не сливались в одну точку. `None` — нет данных: линия в этом месте рвётся, соседние куски рисуются отдельными отрезками; одиночная точка между двумя `None` — кружок того же цвета.

Модуль `bot/vpn_report_chart.py`, функция `render_panel(panel) -> bytes` — чистая функция (описание панели → PNG), без aiogram и без БД: геометрия, цвета и шрифты вынесены в константы, рисование — по функциям (`_draw_header`, `_draw_grid`, `_draw_bands`, `_draw_lines`, `_draw_legend`). Шрифты DejaVu через `ImageFont.truetype`, при отсутствии файла — `load_default()`. Цвет плашки статуса берётся из уровней `domain.vpn_link` (`ok` — зелёный, `partial` — оранжевый, `down` — красный), неизвестный уровень — серый.
