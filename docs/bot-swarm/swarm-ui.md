# Панель роя, карточки, ссылки-команды

## Иерархия (ARCHITECTURE §11)

`/swarm` (алиас `/nodes`) - панель `sw_*` одним сообщением (`edit_text`), «Назад» ведёт выше: панель -> умения / ноды -> карточка ноды -> службы -> карточка службы. Чистый рендер (текст + клавиатура) в `bot/swarm_panel.py`, `bot/node_view.py`, `bot/swarm_view.py`; сетевые вызовы и редрав в `bot/handlers/swarm_panel.py`. Права на callback проверяет `CallbackAuthorizationMiddleware`.

Рой равноправен: карточка одна на все ноды (своя - частный случай `node_id=None`), данные и действия идут через свою ноду с dst-адресом («спроси любого»).

## Ссылки-команды

Навигация по нодам и службам - кликабельными командами в тексте: `/node_<id>` (право `status`), `/svc_<нода>_<служба>` (право `nodes`). Inline-кнопки остаются за действиями. Имена содержат дефисы, команды Telegram - только `[a-z0-9_]` до 32 символов: при генерации `-` -> `_`, непредставимые имена ссылку не получают (имя выводится жирным). Обратный разбор неоднозначен: сопоставление с реальными данными роя, кандидаты от длиннейшего префикса-ноды; спящий кандидат не мешает более коротким. Хендлер включён до apps; неразрешимую ссылку с нашим префиксом объявляем честно.

## callback_data

Сегмент `node_id`: `-` для своей ноды (пустой нельзя - дальше всегда идёт сегмент). Формат живых кнопок в чатах менять нельзя.

## Правила сортировки и состояний

- Порядок нод: проблемные -> активные -> штатно не в сети; сортировка ДО пагинации (иначе пропавший сервер уходит на 2-ю страницу).
- Сервер/VDS (`always_on`), пропавший из сети - авария; не-24/7 нода спит - норма (правило роя п. 4); нода, предупредившая об уходе, выключена нарочно.
- Кнопка «Разбудить» (живая находка 2026-07-20): предлагается и для «не в сети», и для «не отвечает» (PeerLink ещё не заметил обрыв). Не предлагается нодам, которые не `wakeable` (сервер, VDS); при неизвестном типе (старая нода) показывается.
- Шапка `/swarm`: у каждой ноды виден только ПОСЛЕДНИЙ outage - если после сбоя было штатное выключение, сбой из шапки исчезает (сознательно без запросов к истории).
- Внешне управляемая служба (llm): pid, рестарты, время старта неизвестны - показываем только статус по связи.
- Карточка ноды: четыре сетевых запроса идут параллельно (`asyncio.gather`), каждый сам гасит сетевые ошибки. У кого есть право `nodes`, список служб уходит на отдельный экран, «Назначить X» - туда же; у остальных - инлайн в карточке.
- Само-рестарт бота (`handlers/node.py`): ответа ноды не дождаться, прощаемся ДО команды; id callback'а в `app_state` (`self_restart_cb`) защищает от переигрыша, когда Telegram не подтвердил offset до смерти процесса.
- Старые кнопки «Список нод» (`st:nodes`) ведут на сводку роя; пустой `node_id` в callback остаётся валидным.
- Роутеры wake / swarm_panel / torrents_panel подключены ДО status, status «ловит» префикс `st:`; node_links - до apps.

## Кэш wake-реквизитов (`bot/wake_state.py`)

Нода докладывает MAC/IP/broadcast в `get_state()["wake"]`, пока жива; бот кэширует в `app_state` по ключу `wake_info:<node_id>`, чтобы разбудить ноду, когда та уснула или сменила DHCP-адрес (этап 19 п.6). Wi-Fi-нода (arch-t480) в кэш не попадёт - будить нечем. Magic packet шлёт живая нода того же сегмента LAN (`wake_core.find_lan_waker`), так сигнал уходит в правильную подсеть (бот может ходить к ноде через tailscale). Ручной путь - фиксированная машина из `[wake]`.

## Путь до соседа (`nodectl status`)

Строка пира в блоке «Пиры:» дополняется путём: `· 254 мс, потери 13% · через jeeves ~185 мс`. Поля (`rtt_ms`, `loss`, `via`, `via_rtt_ms`) берутся из `get_state()["peers"]` (`NodeRouter.peers_state()`); потери показываются только если > 0, `via` - если запросы идут через ретранслятор. Старые ноды полей не присылают - строка остаётся прежней. Форматтер один: `utils/peer_path.py::format_peer_path`. Экраны бота пиров ноды не перечисляют (`/swarm` показывает ноды по их собственным отчётам), поэтому там путь не выводится.
