# Голос (`bot/voice_stt.py`, `bot/voice_tts.py`, `bot/voice_mode.py`)

## Распознавание голосовых пользователя

Распознаёт служба llm на mycraft (faster-whisper, CPU; `llm/stt.py`); alfred качает байты и передаёт по рою, как для фото. В отличие от фото, нужен РЕЗУЛЬТАТ (транскрипт) раньше начала текстового хода, поэтому явный `wake_core.ensure_service_ready` до отправки байт, а не тихая presence-проверка внутри самого `chat`. Presence-проба перед ним — только ради статуса «шаги» (дешёвый запрос ради UX, тот же компромисс, что у request_alfred).

- Статусы идут через ту же `RichStreamSession`, что и финальный ответ (передаётся вызывающим): «слушаю» и ответ делят один черновик. Где смысл тот же (машина просыпается), переиспользуются те же `STEPS_TEXT`, `ALBERT_UNAVAILABLE`, `ALBERT_HICCUP`, а не параллельный набор фраз (риск `think_style`).
- Решение 2026-08-11: typing при распознавании не горит — за пользователя говорит статус «слушаю»; раньше было два индикатора, typing обещал печатающийся текст, которого ещё нет.
- Инлайн: аудио после base64 ≤ `_INLINE_VOICE_B64_BYTES` (800 000, тот же порядок, что у фото, с запасом от `MAX_MESSAGE_BYTES` 1 МиБ); длиннее — чанками `stt_chunk` (`CHUNK_BYTES` протокола), реальный путь для голосовых на несколько минут. Потом `transcribe_voice` по `session_id` + `expected_size` + `expected_sha256`.
- Успех: сессия НЕ финализируется — черновик «слушаю» остаётся, его сменит ответ Альфреда.
- `transcribe_bytes` — для голосовых, накопленных за отъезд Альфреда (Этап 51, `bot/away_return.py`): без сообщения и статусов.

## Синтез голосового ответа

Синтез делает служба llm (Coqui XTTS v2, CPU; `llm/tts.py`). Данные текут в обратную сторону: готовит аудио нода llm, alfred скачивает — pull-паттерн чанков (`tts_chunk`, как `vpn/service.py::ACTION_APK_CHUNK`), а не push. Любая ошибка — `None`, вызывающий молча откатывается на текст: пользователь никогда не остаётся без ответа.

Статус синтеза — «проговаривает» (не «готовится»): находка 2026-08-12 — время синтеза примерно равно длительности аудио, XTTS проговаривает текст. Референс — голос самого Альфреда (поправка 2026-08-11: первая формулировка намекала на озвучку «со стороны»). После отправки голоса статус-черновик закрывает `VOICE_REPLY_SENT_MD`.

## Голосовой режим

Per-chat тумблер в `app_state` (`voice_reply_mode:<chat_id>` = `on`/`off`), включается естественной просьбой через тул `voice_mode`, не командой. Состояние переживает рестарты — тот же паттерн, что `bot/wake_state.py`.
