# Формы подтверждения (`bot/pending_actions.py`, Этап 45/46)

Альфред — помощник, решает человек. LLM формулирует и сопровождает словами, но не принимает решений и не пишет итог в БД: решение — нажатие кнопки на ОТДЕЛЬНОМ сообщении-форме, текст которой собирает код по шаблону. Живая находка 2026-09-26: заявка связи #5 зависла в pending навсегда — адресат ответил «Не хочу», модель сказала «решение принято», но `reject_relationship` не вызвала (директива с id жила только в chat_loop-задаче, в историю живого /ai не попадала).

- Каждое событие = два сообщения: речь Альфреда (LLM, «желательно»), затем форма/оповещение (код, «гарантированно»). LLM не ответила — `NO_WORDS_TEXT`, форма уходит всё равно.
- Жизненный цикл `pending_actions`: draft (у инициатора, 1 ч) → pending (у адресата, 72 ч) → accepted/rejected; из draft/pending — cancelled/expired. Писатель статуса один — этот модуль; кнопки, будильник tasks и восстановление лишь просят перехода, переход атомарен (`Store.transition_pending_action`), повторное нажатие или гонка с экспирацией не находят строку.
- События `ActionBus`: `action_created`/`action_submitted`/`action_decided`; реакции — подписчики («речь + форма адресату» на submitted, «речь + оповещение инициатору» на decided, при принятии ещё «поздравление + оповещение» адресату — Этап 46: знакомы теперь оба). Сбой подписчика не откатывает переход. Единственный `kind` — знакомство гостей (`relationship`, одна связь без типов, relation всегда acquaintance).
- Стадии речи: `offer` (адресату), `outcome` (инициатору), `welcome` (адресату после «Принять»); meta chat_loop-задачи несёт `pending_action_id` + `pending_action_stage`, `bot/node_events.py` возвращает результат в `on_speech_result`. `claim_speech` вызывается ДО отправки речи: форма уже ушла (страховочный таймер успел с заглушкой) — опоздавшую речь не шлём, иначе она встанет ПОСЛЕ формы. Страховочный таймер = `FIRE_GRACE_S` службы tasks (300 с) + таймаут запроса + запас 60 с.
- Будильник истечения — задача в tasks (персистентная очередь, переживает рестарт бота); tasks недоступна — таймер в памяти, его потеря при рестарте закрывается `recover()` на старте (просроченное истечь, открытое — таймер, недоставленное дослать).
- Формы черновика шлются ПОСЛЕ ответа Альфреда (`flush_drafts` последним шагом хода): тул `request_acquaintance` срабатывает посреди генерации, форма обогнала бы речь.
- Текст формы пишется в `ai_turns` без разметки: модель видит форму в истории треда и не делает вид, что её нет.
- callback_data `pa:<id>:<кнопка>` (s/c/a/r) — только id и вердикт (лимит 64 байта), права проверяет `handle_click` по `from_user.id`: гость не нажмёт за другого, даже если форму переслали. Формат живых кнопок не менять.
- Имя в итоге инициатору — именительным лейблом перед тире: падеж не держим (`full_name` в конфиге только в именительном).

# Дебаг-канал вызовов тулов (`bot/tool_debug.py`)

Сообщение «🔧 Alfred вызвал инструмент: X» (`bot/lifecycle.py::notify_tool_call`) отвечает на «обращался ли», но не на «с чем и что получил». Полный текст не влезает по смыслу (канал шумит на каждой реплике) и по размеру, поэтому прячется за кнопкой «развернуть/скрыть» (`tdbg:show|hide:<token>`). Вход/выход живут в памяти процесса (в callback_data 64 байта, в БД не нужно — отладочный след не должен переживать рестарт); потерялся — кнопка честно скажет `LOST_TEXT`. Прав кнопка не проверяет: сообщение приходит только в чаты, подписанные на дебаг-событие `alfred_tool_call`, и ничего сверх уже показанного не открывает. «message is not modified» при двойном нажатии — не ошибка.
