# Путь одного хода /ai

## Вход (`bot/handlers/ai.py`)

- `/alfred` (в меню) и скрытый алиас `/ai`; неявные входы — любое текстовое/фото/голосовое/стикер-сообщение в личке и `@упоминание` в группе. Неявные входы живут в отдельном `catchall_router`, который регистрируется в `setup.py` последним (после apps), чтобы не перехватывать то, что предназначено другим роутерам (magnet-ссылки и т.п.). `router` с точными фильтрами (команда, реплай на свой тред) регистрируется рано.
- Дизайн диалога — LLM_INTEGRATION_PLAN.md §6: `dialogue_id` = message_id команды, начавшей тред; реплай-цепочка резолвится через `ai_turns` (фильтр `AiReplyContinuation`), а не через дерево реплаев Telegram.
- Без топика и без reply каждое сообщение в личке — новый тред (как `/alfred`); иначе история в личке росла бы бесконечно (живой баг 2026-08-01). Продолжить тред можно реплаем.
- **Private Chat Topics (Этап 32, 2026-08-01):** сообщение внутри топика личного чата (`message_thread_id` не пуст) — `dialogue_id` равен id топика, весь топик один тред, reply не нужен. `/alfred` внутри топика контекст не сбрасывает. aiogram сам пробрасывает `message_thread_id` в `answer()/reply()`. Живой спайк 2026-08-01: `createForumTopic`/`sendMessage(message_thread_id)`/`editMessageText` в топике личного чата отработали с первой попытки (регрессия Bot API 10.0 «message thread not found» на этом боте не воспроизвелась).
- AuthorizationMiddleware не проверяет права на не-командные сообщения, поэтому каждый неявный вход сам проверяет право `required_right(ALFRED)` (иначе тред продолжился бы в чате, у которого право chat@llm отозвали).
- Этап 51 «Альфред в городе»: `away.intercept` первым делом — записка вместо ответа, до голоса/зрения; GPU не трогаем.
- Пустой вызов (`/alfred` без текста, упоминание без текста, `start_dialogue` из приватного входа гостя) — не заготовленная фраза, а `OPENING_PROMPT` для модели (решение 2026-07-23: модель локальная, экономить обращения незачем, одна и та же фраза выдаёт бота). Директивы `OPENING_PROMPT`, `EMPTY_REPLY_PROMPT`, подсказки к фото/стикеру в `ai_turns` НЕ пишутся — только ответ на них. Приветствие без вопроса запускает фоновый портрет Альфреда в кабинете (`Interactives.start_greeting_portrait`, 2026-10-05).
- Фото: `PHOTO_MARKER` в `ai_turns.content`, сама картинка не попадает в историю (`photo_path` — ключ на диске службы llm, считается детерминированно `photo_key_for` без похода в БД), иначе история, гоняемая по сети роя на каждый ход, распухала бы. Ресайз и хранение делает служба llm (`llm/vision.py`), не alfred (слабый CPU, решение 2026-08-10). Лимит — запас от `MAX_MESSAGE_BYTES` (1 МиБ), base64 раздувает на треть. Подпись у фото — `message.caption`, не `text`: до живой находки 2026-08-10 фото-реплай в тред терял подпись.
- Стикер (2026-08-11): Telegram делает статичный thumbnail для любого стикера, декодировать Lottie/webm не нужно; pipeline тот же, что у фото. В отличие от фото — без отказа: у стикера есть emoji, реагировать можно и без превью (`STICKER_PROMPT_NO_IMAGE`).
- Статусные плейсхолдеры «разглядывает стикер/фото» — только rich-режим, plain-фолбэка нет: скачивание — доли секунды.

## Исполнение (`_ask_and_reply` → `_do_ask_and_reply` → `ai_flow.request_alfred`)

- Задача хендлера регистрируется в `ActiveAiChats` (chat_id → `asyncio.Task`). Живая находка 2026-07-24, два захода: останов бота (деплой, `restart_node`) обрывал запрос голой сетевой ошибкой («Connector is closed»); версия, хранившая только `set[int]`, не отменяла задачу, и осиротевший хендлер, когда `_shutdown()` рвал `node_link`, слал «Прошу прощения, что-то пошло не так» то до `RESTART_TEXT`, то после. Теперь `bot/app.py::_shutdown()` рассылает `RESTART_TEXT` и активно отменяет задачи РАНЬШЕ разрыва связей; `CancelledError` не `Exception`, `try/finally` снимает регистрацию молча.
- `try/finally` в `_do_ask_and_reply` гарантирует `rich_session.aclose()` на любом выходе (живая находка аудита пробуждения 2026-08-26, Приложение 5: исключение, пустой ответ или отмена оставляли черновик тикать keep-alive до 30-минутного потолка).
- Формы подтверждения (Этап 45) и формы интерактивов (Этап 47) уходят в `finally` строго ПОСЛЕ речи Альфреда при любом исходе; при отмене задачи (рестарт бота) формы не шлются — `PendingActions.recover()` дошлёт.
- Пустой ответ модели (живая находка 2026-07-29: кончилось окно контекста — декларации тулов плюс выдача поиска; пользователь получал сообщение из одного префикса «Альфред:») в `ai_turns` не пишется, пользователь получает `ALBERT_HICCUP`, админ — подробности.
- Не доставлен ни rich, ни plain (Этап A, 2026-08-30): ответ целиком кладётся в лог узла (раньше пропадал бесследно), админу уходит начало.
- Голосовой режим (тумблер per-chat, тул `voice_mode`): голос ВМЕСТО текста (решение 2026-08-11); любой сбой синтеза — тихий откат на текст; `raw` в `ai_turns` пишется целиком независимо от способа доставки.
- Эмоциональное селфи (2026-10-05, `Interactives.mood_selfie`): реплика уходит подписью к снимку вместо текста; не в голосовом режиме и не в ходе, где уже слали картинку (`take_photo`/`generate_image`); сбой — обычный путь.
- Эпизод графа (Этап 42.2) пишется после доставки ответа, из `ai_turns` берётся персистентный текст хода (с `PHOTO_MARKER`), а не служебный промпт; директивы без сохранённого хода пропускаются.
- Ремарка «Логопеда» (`llm/speech_therapy.py`) — отдельным сообщением ПОСЛЕ ответа, без `html.escape` (она сама генерирует безопасный HTML): колбэк срабатывает до отправки самого ответа, раньше времени слать нельзя. Тот же паттерн ячейки, что `DismissalBox` в `bot/tools.py`.
- Роспуск («ты свободен», тул `dismiss`): тул только назначает уход; исполняет `perform_dismissal` после отправки прощания. Порядок «модель, потом машина»: выгрузка контейнера штатна и быстра, выдёргивать питание из-под WSL2/Docker незачем. Неудача выгрузки модели при режиме «только модель» — `DISMISS_FAILED_TEXT` и уведомление админам; для sleep/off машину гасим всё равно. Таймаут 15 с — команды только ставят задачу, прощание уже сказано. `quiet=True` у `sleep`, чтобы `llm_idle_sleep` не отрендерил «не дождался обращения» поверх прощания.
- Ход закончил тул (`ToolContext.end_turn`, `take_photo`): `SILENT_REPLY` — реплики нет, Альфред заговорит подписью к снимку; отличается от пустого ответа модели (сбой, «Альбегт»).

## Presence / wake и персонажи сбоев

- Сценарий (обсуждение 2026-07-23): если нода недоступна — показать «шаги» (`STEPS_TEXT`), молча разбудить через рой, подождать, затем «Агнольд» (проснулась) или «Альбегт» (не вышло). Имена фиксированные строки: их произносит картавый Альфред («Арнольд»→«Агнольд», «Альберт»→«Альбегт»), сами они «р» выговаривают, поэтому их реплики пишутся без искажений.
- Живая находка 2026-07-24: 30 с мало — winpc не успевала выйти из S3 (POST + загрузка Windows + старт `sa-home-node` + регистрация пира «llm»), «Альбегт» появлялся раньше пробуждения. Первопричина — AC-таймер сна (`powercfg`, 45 мин) снова включился после обновления/смены схемы питания; выключен заново, но код обязан переживать холодный подъём из S3.
- Одна точка готовности — `wake_core.ensure_service_ready` (общая для текста/фото/стикера/голоса и службы tasks). Живая находка 2026-07-27: пока было две копии констант, правку приходилось делать в обоих файлах, и `WAKE_POLL_TIMEOUT_S` значил разное. Прежняя собственная последовательность request_alfred (presence → попытка → wake → вторая попытка) удалена по итогам аудита 2026-08-26 (Приложения 2–4 плана механизма готовности). `CRASHED` (нода жива, служба не отвечает; WoL не поможет) — «Альбегт» + тревожное сообщение админам.
- Живая находка 2026-07-24: внутренний сбой Ollama при живой ноде (`ERR_INTERNAL`) отдавал голый технический текст от лица «Альфреда» без картавости — читалось чужеродно в общем чате. Пользователь явно просил не пускать техническое в чат; `ALBERT_HICCUP` («Альфред на секунду отвлёкся — повторите») — тот же персонаж, админу подробности в личку (определяется по `allowed_commands="*"`).
- Живая находка 2026-08-11: «Альбегт» уходил голым `message.answer()` мимо активной rich-сессии, оставляя черновик «шаги» незакрытым (keep-alive). Единственная точка выхода rich-сессии для «Альбегта» — `_announce_albert`.
- `CLOSING_TEXT` и `RESTART_TEXT` рассылает `bot/node_events.py` (событие, не ответ на сообщение), но тексты — часть персонажа и живут в ai_flow. `RESTART_TEXT` явно НЕ выглядит как сбой (просьба 2026-07-24). `ALBERT_TASK_MISSED` — по событию `task_result(ok=False)` после `PREWAKE_LEAD_S` и `FIRE_GRACE_S` (решение 2026-07-27).
- Пары HTML/MD/plain-текстов — осознанно рядом, а не общий html→markdown хелпер: rich-путь не понимает HTML (`finalize_status` — markdown, `push_status` — plain), расхождение видно с одного взгляда (в отличие от `think_style`, разъехавшегося по трём файлам, находка 2026-08-10).

## Router и think (LLM_INTEGRATION_PLAN.md §7)

- Включать `think=true` на каждый запрос надёжно для расчётов, но раздувает даже «привет» до 30–40 с. Вместо этого сначала лёгкий router-проход (`think=false`, `ROUTER_SYSTEM_PROMPT` без персонажа), потом один персонажный проход с известным уровнем.
- Живая находка 2026-07-25: когда триаж был частью персонажного вызова, модель на фоне 12 правил персонажа проваливала именно триаж (головоломка про кружку с запаянным верхом решена с ходу и неверно, хотя `_SPATIAL_REASONING` был в контексте). Решение владельца: отдельный вызов с маленьким промптом — дороже (гарантированный второй вызов на КАЖДОЕ сообщение, осознанно), но дешевле always-on think. Роутер оценивает по шкале 0..3 (`parse_router_level`), уровень → намерение `REASON_LEVELS`; в параметр модели его переводит профиль на стороне службы llm (`llm/model_profiles.py`), знание про механизм сюда не течёт.
- Router-проход не стримится в rich (вывод роутера пользователю не показывается). Его `router_messages` мутируются `run_chat_loop` и идут дальше в персонажный проход, чтобы Альфред видел результаты тулов.
- `_use_router`: явный `[llm].mode` в config.toml побеждает (legacy-override: `single_call_think`, `router_think` — формат конфига, не удалять); иначе профиль модели (`describe`, кэш 5 мин: профиль меняется только при рестарте службы llm); без профиля — router.
- Ход сцены интерактива (Этап 47) идёт без рассуждения: Ведущий ведёт сюжет, Альфреду остаётся отыграть реплику; рассуждение стоило ~60 с на ход (находка 2026-10-02, router почти всегда давал THINK:1).
- typing («печатает») — решение 2026-08-11: только вокруг вызова, который реально пишет ответ (не роутер, не ожидание пробуждения). С rich-сессией индикатором управляет сама сессия.
- `SURFING_TEXT` (web_search): живой замер 2026-07-27 — три минуты от вопроса до ответа (модель делает несколько поисков подряд, переформулируя запрос). Фолбэк-путь (группы, `typing_plain`): плейсхолдер персистентный, поэтому ОДИН раз за запрос; в rich-пути статус эфемерен, дедуп внутри `RichStreamSession`, гейтинг не нужен. `TOOL_STATUS_TEXT` — «бегущая строка» на каждый тул (Этап 34, находка 2026-08-10), показывается ДО выполнения (`ToolStartSink`); тест `test_tool_status_covers_every_registered_tool` ловит новый тул без фразы.
- Трассировка тулов (`ai_tool_calls`, находка 2026-07-24): «шиза» с часовыми поясами была недиагностируема, пока не стало видно, звала ли модель тул и что получила. Пишет только живой /ai (у службы tasks нет Store).
