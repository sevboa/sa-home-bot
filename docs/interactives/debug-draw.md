# Отладочный /draw и тулы картинок (draw_debug.py, handlers/draw.py, image_tools.py, этап 48–49)

## Тулы `generate_image` и `find_image` (image_tools.py)

Рисует служба llm на mycraft (`llm/imagegen.py`), хранит бот — таблица `images` в своей БД: «покажи ту картинку» не
должно будить mycraft. Повторный показ идёт по Telegram `file_id` без байтов; байты из БД нужны, только если Telegram
`file_id` не принял (тогда шлём байты и запоминаем новый `file_id`). Хранится маленькая копия, `upscale_png` растягивает
целым множителем без сглаживания при отправке. Модуль отдельный (не часть `bot/tools.py`): обработчики там — тонкие
обёртки, а модуль не импортирует `bot.tools` (иначе цикл). Из `ToolContext` берётся утиной типизацией; эпизод графа —
колбэком `remember`. Константы службы — литералы, не импорт из `llm/service.py` (бот не тянет тяжёлую службу). «Нарисуй
себя» (2026-10-05): LoRA облика и короткая примета первой, что Альфред делает и где — из `description` модели.
`prompt_en` — имя параметра до v0.117.0: модель может вспомнить его по истории чата, поддержка оставлена.

## /draw (draw_debug.py + handlers/draw.py)

Режимы генерации руками владельца: подбор архетипов предметов и настроек сцен до передачи Ведущему. Та же служба и
тот же эталон, что `generate_image`; сверху режим, образец и ручки (seed, strength, ip…). Картинки ложатся в `images` с
`purpose='debug'`: `find_image` их не видит, дневной лимит не считает, «/draw clean» удаляет пачкой. Разбор команды —
без aiogram (тестируется без бота). Право `draw`, команда скрыта из меню, кнопки clean — префикс `draw:`. Образец:
`ref=ID`, картинка команды, картинка, на которую ответили; чужой образец ужимается до родного размера SD1.5. Первая сцена
с образцом грузит IP-Adapter (+2.5 ГБ с диска). `neg:` без `|` перед ним тоже негатив (иначе прилипал к описанию).
Пока Альфред в городе (этап 51), рисование ждёт — GPU не трогаем (help/keep/clean работают).
