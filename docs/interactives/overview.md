# Устройство и жизненный цикл хода

## Встраивание в ход /ai (`bot/handlers/ai.py::_do_ask_and_reply`)

1. `Interactives.before_turn` — ДО запроса к модели: идёт ли сцена, нужна ли форма согласия,
   сборка скрытой заметки Альфреду (рамка сцены + подсказка стадии + директива Ведущего + что
   произошло после прошлого действия + журнал). Заодно отдаёт `speech_clear` гостя — он едёт в
   каждый запрос к службе llm.
2. Альфред отвечает как обычно, ответ сразу уходит гостю.
3. `after_turn` — ПОСЛЕ ответа: журнал, вызов Ведущего, рамки темпа. Ведущий гостю НЕ виден
   (решение пользователя 2026-09-27: всё выглядит как обычный диалог с Альфредом). Его `effect`
   копится в `Run.pending_effect` и на следующем ходу уходит Альфреду скрытой подсказкой — о
   случившемся рассказывает сам Альфред.
4. `flush_forms` — последний шаг хода: формы (согласие, смена передатчика), которые попросили
   тул или финал, и кадры катакомб. Форма, посланная посреди генерации, обогнала бы речь Альфреда
   (тот же приём, что `PendingActions.flush_drafts`, этап 45).

Сцены только в личке: в общем чате подсказки сцены сбивали бы Альфреда в разговоре с остальными.
Эффект и завершённость хранятся на гостя глобально, поэтому переключатель после завершения
работает в любом чате. Пока Альфред «в городе» (этап 51, `away`), сцены не продолжаются, а
рисование `/draw` ждёт — GPU не трогаем.

## Согласие

Сцена сначала `offered`: невзначай заданный вопрос сценария («исправить проблему с
коммуникацией?») с «Да»/«Нет», без намёка на игру (решение пользователя 2026-09-27; форма
после ответа лишь фиксирует его, тоже без слов «сценка»/«игра»). «Да» — сцена стартует. «Нет» —
только пауза `DECLINE_COOLDOWN` (у сценария может быть свой кулдаун), не запрет насовсем:
отказавшийся гость не знал про `/interactives on` (решение пользователя 2026-10-02). Запрет
насовсем — только командой `/interactives off`. Без ответа час (`OFFER_TTL`) — как истёкшее, но
без кулдауна: заговорит гость о теме снова — спросим снова.
`BTN_LATER` («Не сейчас») — у форм, разосланных до v0.115.2; `BTN_EXIT` и `EXIT_ALERT` — кнопка
выхода под сообщениями рассказчика (до v0.115.3). Оба обработчика оставлены ради уже
отправленных сообщений.

Канареечные предложения принимаются и словами (`OFFER_YES_WORDS_RE` / `OFFER_NO_WORDS_RE`,
находка 2026-10-11: «Да, проверь, что там внизу» не начинало сцену). Смотрится только начало
реплики («не проверяй» — не согласие), отказ проверяется первым. Ход, где согласие дано словами,
получает `AGREED_BY_WORDS_NOTE`. Просьба о снимке (`PHOTO_REQUEST_RE`) блокирует спонтанный стук
в этот ход: форма влезала между ответом и снимком.

## Живые кнопки

Формы сцены и смены радиостанции и раскрытый перечень действий карточки гасятся следующим
сообщением гостя («гость проигнорировал»): у форм снимаются кнопки, перечень сворачивается в
карточку (`LIVE_BUTTONS_KEY`, пользователь 2026-10-02). Иначе старая форма оставалась нажимаемой
рядом с новой. Callback-коды: `ia:<сценарий>:<кнопка>` (`p l n x s k r i o`) и
`it:<id вещи>:<кнопка>` (`p r s k l n x o i c a b f`) — живые кнопки в чатах, значения не менять.
`it:` коды действий не начинаются с `i`/`f` — это префиксы источника (опись / форма тула).

## Канарейка (этап 59.C, решение владельца 2026-10-10)

Всё новое этапа 59 существует только для гостей из `llm.interactives_canary_user_ids`
(`Interactives.canary_ok`): канареечные сценарии (`Scenario.canary`), вещи (`ItemKind.canary`),
тулы `search`, `walk`, `go`, `act`, `manor_items`, `item_action` (`bot.tools.CANARY_TOOLS`), места
кроме кабинета и положение `alfred_at`. Для остальных гостей ход идёт ровно как до этапа 59 и
в `app_state` ничего не пишется. Формат конфига `interactives_canary_user_ids` менять нельзя.
Порядок `REGISTRY`: радио первым (до этапа 59 он был единственным), канареечные после.
