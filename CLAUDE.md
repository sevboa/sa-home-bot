# sa-home-bot: правила проекта

Общение с владельцем, сообщения коммитов и документация на русском.

## Код
- В `src/` и `tests/` нет комментариев и докстрингов. Допускаются только прагмы (`noqa`,
  `type: ignore`, `pragma:`, `fmt:`, `ruff:`). Код объясняет себя именами и структурой.
  Страж: `tests/unit/test_no_comments_in_code.py`.
- «Почему так», живые находки, инциденты и решения владельца описываются в `docs/<зона>/*.md`.
  Оглавление: `docs/README.md`. Меняешь поведение, обнови раздел своей зоны. Новая находка
  записывается с датой.
- Одна вещь реализована в одном месте. Перед тем как писать хелпер, константу или фейк, загляни в
  `docs/foundation/README.md`. Общие примитивы лежат в `utils/*`, `proto/{errors,chunks,emitter,addresses}`,
  `bot/ui/*`, а тестовые фейки в `tests/unit/support/`. Имена действий и событий протокола
  берутся из `*/protocol.py` и `node/events.py`, литералы не повторяются.
- Реэкспорты ради совместимости не заводятся. Потребители импортируют из канонического места,
  а monkeypatch подменяет имя там, где оно читается.
- Персонажные строки Альфреда не правятся и не переносятся между кодом и TOML без явного запроса.
- Ветки совместимости со старыми нодами, `swarm_panel` без `HIDDEN_MENU_APP_IDS`, `agent/` и
  `PHOTO_DAILY_LIMIT=0` сделаны так намеренно.

## Рефакторинг
- Поведение сохраняется байт в байт:
  - тексты пользователю;
  - callback_data;
  - имена действий, событий и полей протокола;
  - схема БД и ключи app_state;
  - поля конфига;
  - CLI;
  - генерируемые файлы.
- Перед удалением или переименованием символа ищи его по `src/`, `tests/`, `deploy/` и
  `pyproject.toml`, включая строковые ссылки.
- Пункт, который оказался рискованным, не делай, а опиши владельцу.

## Тесты
- Без избыточности: тест на удалённый символ удаляется, копипаста сводится в `parametrize`.
- Сначала запускай затронутые файлы, полный набор в конце. В worktree тесты запускаются с
  `PYTHONPATH=$PWD/src`, иначе editable-установка venv смотрит в основное дерево.
- Полный набор гоняй через скил `devlab-test` (mycraft); локально только если хаб недоступен.
- Задачу агенту (бесплатная модель на mycraft) ставь через скил `devlab`: task.md, подтверждение
  владельца, `nodectl devlab base`, приёмка с ревью; слияние и выкат только по слову владельца.
- `ruff check` прогоняется по изменённым файлам. `ruff format` не применяется к файлам, которые
  уже были неотформатированы, чтобы не плодить шум в диффе.

## Git и окружение
- В дереве могут работать несколько сессий. Никогда не делай `git stash`, `git add -A/.` и
  `commit -a`, коммить только свои файлы поимённо.
- alfred слабый (Celeron N3350, 3.7 GiB): тяжёлое и параллельное запускается по одному.
- Деплой и прод-действия только после явного подтверждения владельца.
