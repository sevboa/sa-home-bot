# Как пользоваться мастерской devlab

Мастерская отдаёт готовый план агенту-разработчику на другой машине. Пока агент работает, вам не
нужно быть в сети: ответы и результат ждут в ящике хаба.

Токен один и тот же для MCP и для git. Имя токена — это ваше имя клиента: задания и ящик видны
только вам. В примерах `<хаб>` — адрес и порт хаба, `<токен>` — ваш токен.

## Цикл работы
1. **Выберите модель.** `devlab_models` — каталог живых моделей. Если нужной нет, задание всё равно
   можно поставить: оно будет ждать, пока модель появится.
2. **Зарегистрируйте проект** (один раз на проект): `devlab_project_add name=<проект>`. Хаб создаст
   пустой репозиторий. Список проектов: `devlab_projects`. В корне проекта должен лежать
   `.devlab.toml` (рецепт окружения, `rules`, `checks`).
3. **Запушьте базу** задачи в ветку `base/<имя>` с тем же токеном:
   ```
   git remote add devlab http://<хаб>/git/<проект>.git
   git -c http.extraHeader="Authorization: Bearer <токен>" push devlab HEAD:refs/heads/base/<имя>
   ```
   Клиенту разрешены создание `base/*` и удаление `agent/*` и `base/*`.
4. **Поставьте задание:** `devlab_submit project=<проект> model=<модель> task=<текст task.md>
   base_branch=base/<имя>`. Шаблон task.md — ресурс `devlab://task-template`. В ответе придёт `id`
   и, если модели нет в каталоге, предупреждение.
5. **Читайте ящик:** `devlab_inbox since=<курсор>`, затем `devlab_ack upto=<курсор>`. Сообщения:
   `started`, `step_done`, `question`, `done`, `failed`, `stopped`. Состояние задания:
   `devlab_status id=<id>`, все ваши задания: `devlab_list`.
6. **Отвечайте на вопросы агента:** `question` переводит задание в `waiting_owner`;
   `devlab_answer id=<id> text=<ответ>` возвращает его в работу. Не хотите ждать:
   `devlab_stop`. `devlab_release` просит исполнителя не держать машину бодрой до вашего ответа.
   Вопрос мог ответить владелец из Telegram: `devlab_status` уже `running`.
7. **Заберите результат.** Когда пришло `done`:
   ```
   git -c http.extraHeader="Authorization: Bearer <токен>" fetch http://<хаб>/git/<проект>.git agent/<id>
   ```
   Коммит в ветке `agent/<id>` — одно схлопнутое изменение поверх `base/<имя>`.
8. **Проверьте по правилам проекта.** Сверьте дифф с `CLAUDE.md`, `AGENTS.md` и `rules` из
   `.devlab.toml`. Есть нарушения или недоделки: `devlab_resume id=<id> text=<замечания>`
   (можно сменить модель: `model=<другая>`). Агент продолжит с `wip/<id>`. За агента не правьте.
9. **Примите.** Перенесите коммит `agent/<id>` в свою ветку, дальше как обычно. Удалите ветки:
   ```
   git -c http.extraHeader="Authorization: Bearer <токен>" push http://<хаб>/git/<проект>.git :agent/<id> :base/<имя>
   ```

Слияние в основную ветку и выкат — только по слову владельца.

## Статусы
`queued` (ждёт исполнителя) → `running` → `waiting_owner` (вопрос к вам) → `running` … →
`done` | `failed` | `stopped`. Из `done`, `failed`, `stopped` и `waiting_owner` задание
возвращается в `queued` через `devlab_resume`.

## Ошибки
Инструмент не бросает исключений: ошибка приходит результатом с `isError` и текстом причины
(неверный статус, чужое задание, нет проекта).
