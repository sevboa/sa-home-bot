# devlab: задача агенту и приёмка

Агент работает на mycraft без тебя, пока ты занят другим. Он слабее Claude: делает мелкие механические
шаги и склонен нарушать правила проекта (чаще всего оставляет комментарии в коде и тестах). Твоя
работа: хорошо поставить задачу и строго принять результат. За агента код не переписывай: замечания
возвращай через `devlab_resume`.

## Условия
- MCP `devlab` подключён (инструменты `devlab_*`) и есть токен `~/.config/sa-home-bot/devlab-token`.
  Нет: `nodectl devlab connect` (он же ставит и обновляет этот скил).
- Проект заведён на хабе (`devlab_projects`), в корне репозитория есть `.devlab.toml`
  (`rules`, `checks`). Нет проекта: `devlab_project_add name=<имя>`.
- Команды `nodectl devlab base|fetch|drop|snapshot` запускаются из каталога репозитория. Токен
  они берут из файла и передают git только окружением `GIT_CONFIG_*`. Токен в argv, командах и
  ответах владельцу не показывай.

## Задача
1. Режь мелко: одна задача = один узел работы, 1-5 шагов, каждый шаг с проверяемым условием
   «готово, когда». Слабой модели нельзя оставлять выбор архитектуры: называй файлы, функции,
   образец рядом лежащего кода. Большое дели на несколько заданий по очереди.
2. Возьми шаблон: ресурс MCP `devlab://task-template`. Разделы: цель, контекст, файлы
   (можно менять / нельзя трогать), шаги, критерии приёмки, тесты, ограничения, бюджет.
3. В «Ограничениях» всегда напомни правила проекта своими словами из `CLAUDE.md`. Для sa-home-bot:
   никаких комментариев и докстрингов в `src` и `tests`, знание кладётся в `docs/`; не трогать
   `.devlab.toml`, `CLAUDE.md`, `pyproject.toml`, `deploy/`; не читать секреты; команды из
   `checks` запускать перед завершением. Для проекта без `CLAUDE.md` перепиши ключевые правила из
   `rules` в `.devlab.toml`.
4. В «Тестах» дай точные команды (узкая на шаг, полная в конце).

## Модель
1. `devlab_models` — каталог живых моделей (имя, цена, окно, остаток лимита). Имя берёшь только
   из каталога, из памяти не подставляй.
2. По умолчанию выбирай бесплатную (`free` в имени или нулевая цена) с самым большим окном и
   подходящими лимитами. Каталог пуст или бесплатной нет: скажи владельцу.
3. Платная модель только с согласия владельца и с потолком в долларах: впиши потолок в раздел
   «Бюджет» task.md и в показ владельцу. Без явного «да» и суммы платную не ставь.

## Подтверждение владельца
Покажи владельцу задачу целиком (task.md), выбранную модель, цену (бесплатно или потолок) и ветку
базы. Жди явного подтверждения. Без него ничего не пушь и не ставь.

## Постановка
1. Закоммить или убери то, что должно войти в базу: агент видит только коммит. Незакоммиченные
   правки в базу не попадут.
2. Запушь базу: `nodectl devlab base <имя>` (по умолчанию `HEAD`, другой коммит: `--ref <ref>`;
   проект: `--project`). Имя: a-z, 0-9, точка, дефис, подчёркивание. Команда печатает ветку
   `base/<имя>`.
3. `devlab_submit project=<проект> model=<модель> task=<текст task.md> base_branch=base/<имя>`.
   Запомни `id` из ответа. Есть `warnings` (модели нет в каталоге): скажи владельцу, задание ждёт.

## Каждое возвращение к работе: ящик
Всякий раз, когда вернулся к задаче или владелец спрашивает «что с агентом»:
1. `devlab_inbox since=<курсор>` (первый раз 0), разбери сообщения, затем `devlab_ack upto=<курсор>`.
   Общая картина: `devlab_list`, подробности: `devlab_status id=<id>`.
2. Сообщения: `started`, `step_done`, `question`, `done`, `failed`, `stopped`.
   - `question`: задание в `waiting_owner`. Ответь сам, если ответ следует из правил проекта и
     задачи, иначе спроси владельца. Ответ: `devlab_answer id=<id> text=<ответ>`.
     Не отвечаешь сейчас и не хочешь держать mycraft бодрым: `devlab_release id=<id>`.
   - `failed`: прочитай причину. Мелочь или слабая модель: `devlab_resume id=<id> text=<что
     исправить>`, при повторных провалах `model=<другая из devlab_models>` (новая модель начнёт с
     `wip/<id>`, task.md и журнала шагов). Задача не нужна: `devlab_stop id=<id>`.
   - `done`: переходи к приёмке.
3. Зависшее `queued` или `running` без вестей: `devlab_status`, при необходимости спроси владельца,
   `devlab_stop`. Ожидание делай опросом с паузой (`sleep 60` в Bash), не одним долгим вызовом.

## Приёмка результата
1. Забрать: `nodectl devlab fetch <id>` — печатает локальный ref `refs/devlab/agent/<id>`
   (одно схлопнутое изменение поверх `base/<имя>`).
2. Ревью диффа: `git diff <база>..refs/devlab/agent/<id>` (база: `merge-base` с этим ref).
   Проверь по `CLAUDE.md` и `rules`:
   - комментарии и докстринги в `src`/`tests` (первая проверка, агенты их оставляют);
   - изменения вне разрешённых путей, секреты, зависимости, лишний рефакторинг;
   - соответствие критериям приёмки, а не только зелёные тесты;
   - документация в `docs/` обновлена, если поведение менялось.
3. Полный прогон на mycraft: `devlab_test project=<проект> ref=agent/<id> wait=240`
   (снимок не нужен). Не дождался: опрос `devlab_status`, подробности `devlab_test_log id=<id>`.
   Подробнее про `wait` и разбор: скил `devlab-test`.
4. Есть замечания или падения: `devlab_resume id=<id> text=<конкретные замечания по файлам и
   строкам>` (при необходимости другая модель), затем снова с «Каждое возвращение». Сам код
   агента не правь, пока не исчерпаны попытки или владелец не сказал иначе.
5. Всё хорошо: отдельный worktree и ветка `dev/<id>`:
   `git worktree add .claude/worktrees/dev-<id> -b dev/<id> refs/devlab/agent/<id>`.
   Мелкие правки и доработки делай там, коммить файлы поимённо (`git add <файлы>`, без
   `add -A`, `stash` и `commit -a`), по правилам проекта пиши сообщение коммита.
6. Отчёт владельцу: что сделано, модель и расход (`devlab_status`), результат полного прогона,
   замечания ревью и что правил сам, ветка `dev/<id>`, открытые вопросы.
7. Чистка после отчёта: `nodectl devlab drop agent/<id> base/<имя>` (на хабе; `wip/*` убирает
   исполнитель) и `git update-ref -d refs/devlab/agent/<id>`. Ветку `dev/<id>` и worktree не
   удаляй, они у владельца.

## Запреты
- Без явной команды владельца: не сливай `dev/<id>` в основную ветку, не пушь в основной
  репозиторий, не выкатывай и не деплой.
- Платная модель без согласия и потолка запрещена.
- Если хаб недоступен (ошибка MCP, `nodectl devlab` не достучался), скажи владельцу; задачу
  без его решения локально вместо агента не выполняй.
